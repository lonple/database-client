# 详细设计：网关与注册中心（横向）

> **横向详细设计**。拓扑摘要亦见 [../架构/01-架构设计.md](../架构/01-架构设计.md)；本地启动见 [../../运维/01-本地启动说明.md](../../运维/01-本地启动说明.md)。

## 1. 结论

| 组件 | 选择 | 说明 |
| --- | --- | --- |
| API 网关 | **Spring Cloud Gateway**（`dbc-gateway`） | 按**服务名**路径转发；后续可加鉴权/限流 |
| 注册中心 | **Nacos**（本地部署） | 服务发现 + 可选配置中心 |

前端**永不直连**业务服务，一律：

```text
dbc-front → dbc-gateway →（Nacos lb://服务名）→ 各 dbc-* 应用
```

**设计即按多模块**：每新增一个子模块服务，只需注册到 Nacos，并在 Gateway 增加（或使用约定式）一条按服务名的路由，前端改用对应前缀即可。

## 2. 模块与服务名一览

| 应用目录 | Nacos 服务名 | 对外路径前缀 | 状态 |
| --- | --- | --- | --- |
| `dbc-gateway` | `dbc-gateway` | （入口本身） | 已落地 |
| `dbc-usercenter` | `dbc-usercenter` | `/dbc-usercenter/**` | 已落地 |
| `dbc-manage` | `dbc-manage` | `/dbc-manage/**` | 已落地规划 |
| `dbc-sqlwork` | `dbc-sqlwork` | `/dbc-sqlwork/**` | 已落地规划 |
| `dbc-audit` | `dbc-audit` | `/dbc-audit/**` | 已定规划 |

规则：**目录名 = `spring.application.name` = URL 第一段**。

## 3. 调用链

```
浏览器
  → Vite 或 Nginx
      → dbc-gateway :8003
          → Path=/dbc-usercenter/** → lb://dbc-usercenter（:8004）
          → Path=/dbc-manage/**     → lb://dbc-manage
          → Path=/dbc-sqlwork/**    → lb://dbc-sqlwork
          → Path=/dbc-audit/**      → lb://dbc-audit
```

### URL 示例

| 前端请求 | Gateway | 后端实际路径 |
| --- | --- | --- |
| `POST /dbc-usercenter/auth/login` | StripPrefix=1 | `/auth/login` |
| `GET /dbc-usercenter/users` | 同上 | `/users` |
| `GET /dbc-sqlwork/execute`（未来） | 同上 | `/execute` |

## 4. 路由策略（可扩展）

### 方式 A：每服务一条显式路由（清晰，一期推荐）

```yaml
spring:
  application:
    name: dbc-gateway
  cloud:
    nacos:
      discovery:
        server-addr: 127.0.0.1:8000
    gateway:
      discovery:
        locator:
          enabled: false
      routes:
        - id: dbc-usercenter
          uri: lb://dbc-usercenter
          predicates:
            - Path=/dbc-usercenter/**
          filters:
            - StripPrefix=1
        # 新增服务复制一段，改 id / Path / uri
        # - id: dbc-manage
        #   uri: lb://dbc-manage
        #   predicates:
        #     - Path=/dbc-manage/**
        #   filters:
        #     - StripPrefix=1
```

### 方式 B：发现定位器（少改配置，自动按服务名）

```yaml
spring:
  cloud:
    gateway:
      discovery:
        locator:
          enabled: true
          lower-case-service-id: true
```

启用后访问形态多为 `/dbc-usercenter/**` 自动转到服务（具体是否还要 StripPrefix 以实现为准）。  
一期建议 **方式 A**，路径行为可控；模块多了再评估 B。

## 5. 业务服务注册示例（dbc-usercenter）

```yaml
spring:
  application:
    name: dbc-usercenter
  cloud:
    nacos:
      discovery:
        server-addr: 127.0.0.1:8000
        metadata:
          mtls-port: 8044   # 仅提供 mTLS 的服务需要；audit 用 8048
```

新模块复制同一段，只改 `name` 与端口。

## 6. 本地与 Nacos

- 本地 Nacos：服务发现 `127.0.0.1:8000`，控制台 `http://127.0.0.1:8001`。
- Gateway、各 `dbc-*` 均注册；联调前在控制台确认实例健康。
- **不在设计里写死业务服务 IP / 容器名端口**；Gateway 转发一律 `lb://服务名`。
- **业务服务之间**同样禁止直连：HTTP 用 `http://{spring.application.name}` + `@LoadBalanced RestClient`；mTLS 用 `discovery://{服务名}`，由 Nacos 选实例并以 metadata `mtls-port` 拼 HTTPS 基址（见 `DbcServiceDiscoveryConfiguration`）。
- 逃生舱：配置写成 `https://host:port` / `http://host:port` 绝对地址时可绕过发现（仅排障）。
- 提供 mTLS 的服务（usercenter / audit）注册时必须带 metadata `mtls-port`。
- 业务端口从 **8003** 自增（gateway / usercenter / front / 后续模块），勿占用 8000、8001。

开发代理示例：

```text
Vite（:8005）：
  /dbc-usercenter → http://127.0.0.1:8003/dbc-usercenter
  /dbc-manage     → http://127.0.0.1:8003/dbc-manage
  /dbc-sqlwork    → http://127.0.0.1:8003/dbc-sqlwork
  /dbc-audit      → http://127.0.0.1:8003/dbc-audit
```

生产 Nginx：

```text
/           → front
/dbc-**     → gateway:8003
```

## 7. 新增子模块检查清单

4. 前端 API 前缀改为 `/dbc-xxx`
