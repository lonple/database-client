# 需求设计

> **文档定位**：业务结构、功能清单与需求规格（权威业务口径）。  
> **顶栏一级菜单（已定）**：首页 → SQL 工作台 → **权限管控** → 资产管理 → 用户中心 → 系统管理。  
> UI 交互见 [../详细设计/06-前端与界面设计.md](../详细设计/06-前端与界面设计.md)；技术落点见各模块详设与 [../架构/01-架构设计.md](../架构/01-架构设计.md)。

## 1. 产品目标

企业级数据库客户端平台：统一登录与组织权限，登记并治理数据资产，在工作空间内协作授权后，经受控执行面访问目标库，并留存审计。

硬边界：

1. 浏览器不直连目标库；目标库访问**只经** `dbc-sqlwork`。
2. `dbc-manage` 为管控面（资产/授权/策略），不持目标库长连接执行 SQL。
3. 人员、角色、功能权限、组织、应用凭证归 `dbc-usercenter`；系统管理（应用登记等）同属用户中心能力，顶栏独立入口。
4. 服务间调用走用户中心 **mTLS + 代签**（见详设签名）。
5. 平台库与目标库连接池分离：元数据与密文在 manage；运行时池在 sqlwork。

默认账号：`admin` / `admin`（BCrypt）；角色超级管理员。

## 2. 业务结构与服务域

| 业务域 | 服务 | 定位 |
| --- | --- | --- |
| 用户与系统 | `dbc-usercenter` | 人、组织、角色、功能权限、JWT、应用 mTLS/代签 |
| 资产管理 | `dbc-manage` | 实例/连接、工作空间、数据权限、安全策略（管控面） |
| SQL 工作台 | `dbc-sqlwork` | 选空间、写 SQL、元数据、执行（执行面） |
| 审计 | `dbc-audit` | SQL 执行审计 + 业务操作审计；顶栏「审计日志」 |
| 入口 | `dbc-gateway` + `dbc-front` | 统一网关与唯一前端 |

历史示意名 `dbc-datasource` / `dbc-asset` / `dbc-execution` 废止。目录名、`spring.application.name`、Gateway 前缀三者一致。

### 2.1 概念分层

| 层 | 管什么 | 不管什么 |
| --- | --- | --- |
| 功能权限 / 内置角色（usercenter） | 菜单与接口；谁可创建工作空间（`DB_ADMIN`） | 空间成员、挂载、成员授权 |
| 部门数据范围（usercenter → manage asset） | 实例/连接可见与可写；授入空间时可选连接 | 空间成员关系 |
| 工作空间 + 全局管控（manage·auth） | 空间、成员、资产/成员授权、全局策略（阻断/告警/二次鉴权） | 连接密码 CRUD；独立风控引擎（后续） |
| 执行面（sqlwork） | 选空间、多会话编辑、批执行、事务会话、调 manage 鉴权 | 授权主数据 |

### 2.2 协作关系

```
前端
  ├─ 管控类 → /dbc-manage/**
  ├─ 工作台 → /dbc-sqlwork/**
  ├─ 用户/系统 → /dbc-usercenter/**
  └─ 审计   → /dbc-audit/**（规划）

dbc-sqlwork 执行链路：
  → manage：工作空间鉴权 + 全局策略（可二次鉴权 ticket）
  → runtime（池化或会话租约连接）执行
  → 执行日志 / 审计（规划；现可结构化日志）
```

## 3. 角色与职责

### 3.1 平台内置角色（usercenter）

| 角色 | code | 要点 |
| --- | --- | --- |
| 超级管理员 | `SUPER_ADMIN` | 全公司 data-scope；系统管理；功能权限最广 |
| 系统管理员 | `SYS_ADMIN` | 组织与用户运营；默认部门及子部门范围 |
| 数据库管理员 | `DB_ADMIN` | **唯一**可创建**公司**工作空间 / 变更公司空间所有者（业务 API 在 manage） |
| 数据操作人员 | `DATA_OPERATOR` | **仅** SQL 工作台 + 个人空间入口；默认无公司侧资产管理/权限管控/全局管控 |

平台「数据操作人员」与**空间内角色**「数据操作人员」（`OPERATOR`）**不是同一实体**，命名相近但职责不同。

### 3.2 空间内角色（manage）

| 角色 | 说明 |
| --- | --- |
| 空间所有者 | 默认创建者；不可移出；公司空间仅 `DB_ADMIN` 可更换所有者；更换后原所有者降为空间管理员 |
| 空间管理员 | 成员、挂载、授权、运营；不可自行撤销所有者 |
| 数据操作人员 | 可进空间；连接使用权完全取决于成员授权；**不可改**他人资产与授权配置 |

空间管理员可：加人/移除（所有者除外）、设管理员、连接授入/移出（受本人 data-scope 或个人域规则）、成员授权。

## 3.3 个人空间（已定）

> 交互定案：**进入/退出个人空间（上下文切换）+ 视觉补强**；**不**再并列「我的实例/我的连接/我的工作空间」菜单（避免重复）。

### 概念

- **个人空间 = 一种特殊工作空间**（`type=PERSONAL`），与公司工作空间（`type=COMPANY`，默认）并列。
- **每用户最多 1 个**；创建后本期**不做**删除/停用（设计预留，实现后置）。
- 个人空间内可登记**个人实例/连接**，并对该默认个人工作空间做成员授权。

### 入口与域切换

| 项 | 规则 |
| --- | --- |
| 右上角 | 只显示用户名（**不**显示角色）；点击展开菜单含「个人空间」 |
| 权限码 | `usercenter.personal.space.view`（名称可微调）；**默认绑定全部平台角色** |
| 点「个人空间」 | 进入**个人空间首页**（所有人同一套内容）：未创建 →「创建」；已创建 →「进入」 |
| **进入个人空间** | 整站进入个人域：顶栏可见首页 / SQL 工作台 / 权限管控 / 资产管理（按个人域能力） |
| **退出个人空间** | **明显出口**（顶栏域徽章旁「退出个人空间」+ 用户菜单可再放一项）；退出后回到公司域 |
| 视觉补强 | 顶栏 **「当前：个人空间」** 徽章/色条；侧栏文案加「（个人）」前缀（仍为同一路由，不增菜单项） |

### 个人域内菜单

| 一级 | 侧栏 | 说明 |
| --- | --- | --- |
| 首页 | — | 个人空间首页（创建/进入说明；已进入后可放快捷入口） |
| SQL 工作台 | — | 可选本人个人空间及**被授权**的他人个人空间 |
| 权限管控 | **仅工作空间授权** | **无**全局管控 |
| 资产管理 | 实例、连接 | 仅个人资产列表 |

### 资产与挂载

- 个人实例/连接：**按所有者用户隔离**；公司资产仍按部门 data-scope。
- **个人资产只能挂到本人个人工作空间**；**不可**挂到公司工作空间，也**不可**挂到他人个人工作空间。
- 公司连接仍按原规则挂公司工作空间（及既有 data-scope）。

### 被授权人

- 所有者将用户加入个人工作空间并授权后，对方**只能从 SQL 工作台选空间进入执行**。
- **不能**从「个人空间」入口进入对方空间，**不能**改对方资产/授权。

### 三套首页内容

| 场景 | 内容 |
| --- | --- |
| 管理员等（非 `DATA_OPERATOR`）默认首页 | 产品快速上手 + SQL 执行业务流程 |
| `DATA_OPERATOR` 默认首页 | 独立内容：工作台引导 + 个人空间说明 |
| 所有人点「个人空间」后的首页 | **同一套**个人空间首页（创建 / 进入） |

### 隔离摘要

| 数据 | 隔离规则 |
| --- | --- |
| 个人空间 / 个人实例 / 个人连接 | **按人**（所有者） |
| 公司工作空间 / 公司实例 / 连接 | **保持原规格**（部门 data-scope + 空间成员授权） |
| 全局管控 | 仅公司域；个人域不展示、不配置 |

### 4.1 工作空间

- 与部门**无归属关系**；只引用连接，不复制账号密码。
- 类型：`COMPANY`（公司，默认）| `PERSONAL`（个人，每用户至多 1 个）。
- 首期粒度：**连接**；可扩展库 → 模式 → 表。
- 同一连接可挂多空间；运行时按**当前选中空间**独立计算，**禁止多空间权限并集**。
- 公司空间授入：只能选本人 data-scope 内**公司**连接；挂载后成员执行权不再按部门二次过滤。
- 个人空间授入：只能选**本人个人连接**；不得挂公司连接、不得挂他人个人连接。

### 4.2 成员与授权

工作空间详情 **仅两个 Tab**：**资产授权**、**成员授权**（不再单独设「成员」Tab；空间角色管理收纳在成员授权页内）。

- **资产授权（空间上限）**：可选多个连接；每个连接可「整个连接」或自定义范围——库（全部/指定）、模式下（全部/指定表）。再勾选 DML/DDL。成员授权不得超出此上限。
- **成员授权（三步向导）**：
  1. **选择用户**（分页多选；未在空间者保存时自动加入，默认空间角色「数据操作人员」）
  2. **选择授权对象**（可多连接；整连接 / 部分库 / 库下部分或全部模式 / 模式下全部或部分表；右侧展示已选摘要）
  3. **选择权限**（SQL 操作勾选）
- 成员授权页另提供紧凑「空间成员」列表：设管理员 / 取消管理员 / 移除（所有者除外）。
- 可选能力：某成员「跟随空间全部资产授权」仍可作为快捷模式保留。

```
资产授权（空间上限） → 成员授权（≤ 空间） → SQL 工作台可用
```

对象范围编码：`CONNECTION` | `DATABASE` | `SCHEMA` | `TABLE`（兼容旧值 `ALL_TABLES` / `SPECIFIC_TABLES`）。
### 4.3 全局管控（权限校验，非风控）

> **已废止**原「高危指令」独立业务；策略统一落在全局管控。后续若单独做风控模块，再另起设计。

- 对**指定 SQL 操作类型**在选定工作空间范围内生效；**不论何人**执行，命中后按策略处理。
- 不能替代工作空间成员/资产授权；判定顺序上**先过空间授权，再套全局策略**。
- 字段：管控名称、管控指令（SQL 操作多选，提供「全部」快捷）、管控策略、管控空间（默认全部空间，含之后新建；可改指定多空间）。
- 策略：
  | 策略 | 行为 |
  | --- | --- |
  | **阻断** | 不执行；执行日志记阻断（标红） |
  | **告警** | **仍执行**；执行日志记告警并标红 |
  | **二次鉴权** | 需校验当前用户密码；通过后发 **30s 一次性 ticket**，**同一会话窗口**内共用；过期重验。失败则**终止当前被管控语句及后续批内语句** |
- 多规则命中优先级：**阻断 > 二次鉴权 > 告警**；同级按排序/创建时间。
- 支持增删改查；权限码 `auth.global.policy.view` / `operate`。

### 4.4 执行判定顺序

```
功能权限（可进工作台）
  → 已选择当前工作空间 / 会话窗口
  → 是成员且空间有效
  → 连接已挂载且成员授权满足（语句类型 + 表）
  → 全局管控策略（阻断 / 二次鉴权 / 告警）
  → 允许执行（或告警后执行）
```

### 4.5 SQL 工作台执行与会话（已定）

| 能力 | 规则 |
| --- | --- |
| **会话窗口** | 编辑器多 Tab；各窗口状态互不影响（连接/库/schema/自动·手动/SQL/结果/日志） |
| **提交模式** | 默认**自动提交**；可切**手动提交**。手动模式下**须用户执行 `BEGIN` 才开启事务**（不隐式开事务）；未 `BEGIN` 前每条语句仍自动提交。工具栏可提示，并可提供提交/回滚按钮（等价 `COMMIT`/`ROLLBACK`） |
| **连接租约** | 自动提交走连接池短连接；进入事务（`BEGIN`）后**独占连接**直至 `COMMIT`/`ROLLBACK`/关 Tab/超时 |
| **闲置清理** | 无可执行活动的会话超时清理（可配；建议闲置 30min，事务中闲置 15min）；清理时未提交事务回滚。用户再使用时**恢复 UI/会话元数据并重新分配连接**（无法恢复已回滚数据），并提示超时 |
| **批执行** | 一次可提交多条 SQL；**Druid 按方言拆分**；**遇错停止**；每条一句执行日志；多个 SELECT → 多个结果 Tab |
| **自动 vs 手动批** | 自动：每句各自提交；手动且已 `BEGIN`：同批后续语句同一事务 |
| **二次鉴权失败** | 当前句不执行，批内后续停止；此前在自动提交下已成功的句子保持已提交；若已在事务中则已执行句仍未提交 |
| **限额（可配）** | 每用户会话数默认 10；单批语句数默认 50；单结果集默认 1000 行 |

### 4.6 典型场景与非目标

| 场景 | 期望 |
| --- | --- |
| DB_ADMIN 创建空间 | 本人为所有者 |
| 改所有者 | 原所有者降为空间管理员 |
| 管理员挂连接 | 仅 data-scope 内可选 |
| 加人未授权 | 能进空间，不能用连接 |
| 授权全部后新挂对象 | 跟随具备 |
| 指定授权后新挂对象 | 不具备 |
| 全局阻断某操作 | 即使有写授权也不执行 |
| 全局告警某操作 | 执行成功，日志标红告警 |
| 全局二次鉴权 | 密码 + ticket 通过后执行 |

非目标：空间隶属部门、自动同步成员、用空间替代资产管理、列/行级权限、独立高危/风控引擎（后续）、脱敏细则。

已确认：所有者更换降级、全局策略三态、平台恢复 `DATA_OPERATOR`（仅 SQL+个人空间入口）、个人空间域切换 + 视觉补强、个人资产仅挂本人个人空间、授权全部完全跟随空间、废止原高危独立模块。

## 6. 功能权限（需求约定）

- 码制：`{服务短名}.{功能路径}.{view|operate}`，段用 **`.`** 分隔，**不用 `-`**；`operate` 含 `view`。
- usercenter 权限 Flyway 种子；其它服务启动 mTLS 注册并只增绑定角色。
- 权限管理页只读定义；无菜单权限不显示；误入回首页。
- 进入 SQL 工作台需功能权限，仅有空间成员身份不能绕过。

**manage 权限码（已定）：**

| code | 用途 | 默认绑定角色 |
| --- | --- | --- |
| `manage.instance.view` / `operate` | 实例（公司域绑定 SUPER_ADMIN、SYS_ADMIN、DB_ADMIN；个人域进入后按所有者隔离使用） | 公司默认：SUPER_ADMIN、SYS_ADMIN、DB_ADMIN |
| `manage.connection.view` / `operate` | 连接（同上） | 同上 |
| `auth.workspace.view` / `operate` | 工作空间授权（公司创建仍要 DB_ADMIN；个人空间自助创建用个人域规则） | **SUPER_ADMIN、DB_ADMIN**（个人域进入后所有者可管自己的空间） |
| `auth.global.policy.view` / `operate` | 全局管控（**仅公司域**） | **SUPER_ADMIN、DB_ADMIN** |
| `usercenter.personal.space.view` | 个人空间入口（用户菜单） | **全部平台角色**（含 DATA_OPERATOR） |
| `sqlwork.execute` / `sqlwork.meta.view` | SQL 工作台 | SUPER_ADMIN、SYS_ADMIN、DB_ADMIN、**DATA_OPERATOR** |

- 一级「权限管控」：公司域任一 `auth.*.view`；个人域仅 `auth.workspace.*` 且无全局管控菜单。
- 一级「资产管理」：公司域任一 instance/connection view；`DATA_OPERATOR` 默认不显示，**进入个人空间后**显示个人资产菜单。
- 个人空间创建不要求平台 `DB_ADMIN`（每用户自助一个）；公司工作空间创建仍仅 `DB_ADMIN`（及超管等）。

部门 data-scope：`ALL` | `DEPT_AND_CHILDREN` | `DEPT_ONLY` | `CUSTOM`；多角色**并集**；**仅作用于公司资产**。细则见 usercenter 详设。

## 7. 实现顺序（需求视角）

1. 权限码与菜单：权限管控 / 资产管理拆分；工作空间迁入权限管控（已落地）  
2. 全局管控 CRUD + 执行期裁决（含二次鉴权 ticket）  
3. sqlwork 批执行、执行日志、多结果 Tab（已落地主干）  
4. **个人空间**：权限码 + 域切换 UI + 个人工作空间/资产隔离 + 挂载校验  
5. 平台角色 `DATA_OPERATOR` 种子与三套首页  
6. 会话窗口 + `BEGIN` 租约手动事务 + 闲置清理  
7. audit ingest + SQL 审计查询（可并行）  

首条闭环：空间授权 + 全局策略 → sqlwork 批执行受限 → 结果/日志。
