## 1. 要解决什么问题

在已有「智能问数」能力之上，为开发 / DBA / 业务运维提供**可回归的问数质量测评**：

1. 用贴近生产的业务库（`company`）与**故意残缺**的库外表注释，模拟真实元数据缺口；
2. 用内置 + 自定义用例（自然语言问题 + 期望 SQL + **预置验证逻辑**）批量驱动问数；
3. 测评模式下：**自动保存工作流并执行**；遇 HITL 时按用例 `case_key` **写死补充**或**故意不补全**；
4. 用期望 SQL **现场执行**的结果与问数结果比对，输出正确率与分层指标。

一句话：**选空间 → 测评空间 → 测评工程（引用模板 + 自定义用例）→ 勾选用例建任务 → 自动跑批比对 → 任务详情看指标。**

---

## 2. 用户与场景

| 角色 | 诉求 |
|---|---|
| 问数研发 / 算法 | 回归提示词与模型；看分层正确率、HITL、拒答是否合理 |
| DBA / 平台 | 在真实风格脏数据与缺注释下，日常查明细/对账是否稳 |
| 业务运维 | 自定义本域用例，验证「自己的问题」能否稳定出数 |

**非目标：** 替代 BI 指标平台；替代手工 Chat 探索（工作台仍保留人工确认执行）。

---

## 3. 信息架构

```text
智能问数（选工作空间后）
 ├─ 问数工作台          ← 现有 AskProject / Chat / 人工执行
 └─ 测评空间
      ├─ 左侧：测评工程（创建 / 删除；引用模板）
      ├─ 右侧：用例列表（模板引用 + 工程自定义；勾选 → 创建任务）
      └─ 右上：测评任务管理 → 历史任务 / 详情（逐条结果 + 汇总指标）
```

创建测评工程时字段与问数工程对齐思路：

| 字段 | 说明 |
|---|---|
| 工程名称 | 必填 |
| 测评模板 | 必选，**引用**内置模板（不复制快照；改模板影响未覆盖的引用用例） |
| 备注 | 可选 |
| **数据来源** | 同问数工程：连接 + 库（+ PG schema），指向测评库 `company` |
| **工作连接** | 同问数工程：临时表 / 结果落库 |

## 4. 测评库与元数据（数据准备）

### 4.1 业务库 `company`（可删重建）

| 项 | 定稿 |
|---|---|
| 画像 | 中型 IT 公司；用户日常运维查明细 / 对账 / 简单统计 |
| 员工 | **累计 1000**（含离职；期末在职约 750～850） |
| 时间窗 | 约 3 年 |
| 日考勤 | 约 **55～70 万**（按在职均值 × 工作日 × 覆盖率；不冲 100 万） |
| 其它 | 客户 ~300、项目 ~150、订单 ~1200、工资条 ~3 万、报销万级 |
| 脏数据 | **有意识缺陷包**（空值、口径冲突、需抽样码值），非纯随机 |

### 4.2 库外表注释 Markdown

- 路径建议：`scripts/demo-company/metadata/db-structure.md`（单文件表结构；部分枚举有取值说明）
- **不**写入数据库 COMMENT（贴近生产缺表述）
- **不**写常用枚举全集（逼模型列抽样 / profile）
- 后续由工具解析 Markdown 注入问数 Tool 侧（本期先产出文档）

另备「出题人口径」（不对模型开放）：在职定义、金额用头表还是明细等，保证期望 SQL 可写死。

## 5. 用例体系

### 5.1 统一存储

所有测评用例一张表（或等价实体），用字段区分：

| scope | 含义 |
|---|---|
| `TEMPLATE` | 内置模板用例（只读维护） |
| `PROJECT_CUSTOM` | 某测评工程的自定义用例 |

分页可按模板 / 工程一并查询。每条用例有全局唯一 **`case_key`**（测评 HITL 补话查找键）。

### 5.2 分类与配额（模板级）

| 大类 | 数量 | 说明 |
|---|---|---|
| 单表条件查询 | 100 | 含业务键点查配额 |
| 多表可直接关联条件查询 | 100 | FK 清晰 |
| 多表复杂治理条件查询 | 100 | 见 §5.3 三分法 |
| 单表统计 | 100 | |
| 多表关联条件统计 | 100 | |
| 多表复杂治理统计 | 100 | 见 §5.3 三分法 |

另建议在各类内嵌入 TopN/排序、时间窗口、否定条件配额（不必单独开大类）。

### 5.3 复杂治理类三分法（条件 / 统计各 100）

| 子类 | 占比 | 行为预期 | 测评跑批策略 |
|---|---|---|---|
| **复杂治理（看板式）** | **50%** | 口径相对清晰，多表汇总/清洗后应一次出数 | 自动保存并执行；**不**注入 HITL |
| **中断补全** | **30%** | 语义不足 → 系统中断（HITL）→ 按 `case_key` 取预置补充话术续跑 → 最终可出数并比对 | 写死 `hitl_replies[]`，自动续跑 |
| **中断不补全** | **20%** | 信息故意不全；**正确行为是不能查出业务数据**（拒答 / 保持中断 / 明确失败） | **不**注入补充；期望终态 = 拒绝出数（见比对规则） |

自定义用例创建时须能选择上述子类，并维护 `hitl_replies`（仅补全子类）与验证逻辑。

### 5.4 用例必填：验证逻辑（设计时确定）

每条用例在出题时选定一种比对方式，例如：

| compare_mode | 说明 |
|---|---|
| `key_set` | 指定业务主键 / 组合键，结果集按键做集合相等（列子集可配置） |
| `order_by` | 指定排序列（及方向），按序逐行比对 |
| `scalar` | 单行单值（或固定少量列） |
| `empty_or_refuse` | 用于「中断不补全」：问数侧不得产生有效业务结果集 |

数值容差、NULL 相等、列名大小写规范化等写在用例或模板默认策略中。

**金标结果：** 一律由 **期望 SQL 在同数据来源连接上现场执行** 得到，再与问数执行结果比对（「中断不补全」可不执行期望 SQL，或期望 SQL 本身用于证明「有充分信息本可查出」仅作出题参考，不参与通过判定）。

## 6. 测评任务与跑批

1. 在工程用例列表勾选 → **创建测评任务**（快照：用例文本、期望 SQL、验证逻辑、HITL 配置拷贝进任务，避免事后改用例改写历史）。
2. 任务异步/可跟踪执行；右上角 **测评任务管理** 看历史。
3. 详情：逐条状态 + 汇总指标。

### 6.1 与人工问数的差异（测评模式）

| 点 | 问数工作台 | 测评模式 |
|---|---|---|
| 保存工作流 | 用户确认 | **自动保存** |
| 执行 | 用户点击 | **自动执行** |
| HITL | 人工在会话补信息 | 按 `case_key` **写死补全** 或 **故意不补** |
| 结果 | 弹窗给人看 | 结构化落库供比对 |

问数服务需提供：**提交问题 →（测评编排）生成并自动跑完 → 返回 SQL/结果/HITL 轨迹** 的能力；不得要求前端模拟人工点保存。

### 6.2 汇总指标（最少）

| 指标 | 含义 |
|---|---|
| 问数失败数 | 生成失败 / 执行异常 / 超时等 |
| 有结果数 | 产出了结果集（含截断） |
| 完全正确数 | 按用例验证逻辑 100% 通过 |
| ≥80% 正确数 | 按用例约定的部分匹配（如行级 Jaccard / 键对齐列匹配率） |
| （建议）中断补全后通过数 | 仅 HITL-补全子类 |
| （建议）中断不补全「正确拒答」数 | 未泄露有效业务结果 |
| （建议）误出数（不补全却查出） | 记为失败，单独暴露 |

## 7. In / Out of Scope

### In Scope

- 选空间后双入口；测评工程 CRUD（删除需确认）；模板引用；统一用例表；任务与详情；自动跑批；结果比对与指标；测评库重建与元数据 MD。

### Out of Scope（本期）

- 改模板的版本化/灰度发布工作流（先引用即时生效）。
- 多模型 A/B 对比 UI（接口可预留 `model_profile`）。
- 将期望结果集整表入库（只用现场执行）。
- 测评任务跨工作空间迁移。

## 8. 方案结论

| 议题 | 结论 |
|---|---|
| 工程模型 | 测评工程 ≠ AskProject；复用 workspace + 同源连接配置模式 |
| 模板 | **引用**，非复制 |
| 跑批 | 测评专用编排：自动保存 + 执行 + HITL 策略 |
| 比对 | 用例级 `compare_mode`；金标 = 期望 SQL 现场执行 |
| 治理三分 | 50% 看板 / 30% 中断补全 / 20% 中断不补全（应拒答） |
| 数据 | 员工 1000；日考勤约 55～70 万；MD 库外 |
