# 智能问数需求分析

| 项 | 内容 |
|---|---|
| 版本 | v0.6 |
| 日期 | 2026-09-28 |
| 工程 | `database-client`（DBC） |
| 范围 | 工作连接工程、Chat/工作流执行、会话日志与结果弹窗、**大模型运行监控** |
| 状态 | 方案拍板修订（LLM 运行监控） |
| 平台硬边界 | 目标库访问**只经** `dbc-sqlwork`；浏览器不直连目标库 |
| 技术倾向 | 独立服务 `dbc-askdata`（Python · FastAPI · LangGraph · 复杂分支 Deep Agents）；平台元数据在 **PostgreSQL schema `askdata`**；不采用 DeerFlow 底座 |

> 与平台总需求关系：本文件为智能问数专项；平台总规格见 [01-需求设计.md](./01-需求设计.md)。  
> **测评空间 / 自动跑批 / 用例回归**见专项 [03-智能问数测评需求分析.md](./03-智能问数测评需求分析.md)（不改变本文件对「人工工作台」的约束）。

## 1. 要解决什么问题

在 DBC **工作空间**内，业务/数仓人员以「问数工程」为单位，用自然语言与大模型会话完成问数：

1. NLU → 元数据 → 涉表判定 → 探测 /（本地）抽样 / 分析；
2. 生成治理 SQL 与查询 SQL，组装为**图形工作流**（**无 EXPLAIN 节点**）；
3. Chat **只负责生成**草稿，用户决定是否**保存**到工程下；
4. 用户在 **Chat 或工作流页**点击**执行**，经 sqlwork **按节点顺序执行**；可**停止**；
5. 执行时：**会话窗口内**滚动展示执行日志与节点成功/失败；**最终结果**以入口卡片呈现，**点击弹窗**查看数据表；
6. 工作流画布页：节点态 + 下侧日志；结果同样**点击弹窗**查看；
7. 缺权限等 **HITL**；方言按连接元数据选型。

一句话：**选空间 → 建工程（必选工作连接）→ Chat 生成 → 用户执行（临时表/结果落工作连接）→ 会话看日志、弹窗看结果；碰库走 sqlwork。**

## 2. 交互与信息架构

| 层级 | 内容 |
|---|---|
| 进入前 | 必须选择工作空间 |
| 进入后顶栏工具区 | **仅**「工作空间」切换下拉 |
| 左侧 | 目录两级：父=工程，子=已保存工作流 |
| 右侧 | 点工程 → Chat；点工作流 → 图形画布 + **执行/停止** + 下侧执行日志 |

### 2.1 创建问数工程

创建时必填：

| 字段 | 说明 |
|---|---|
| 名称 | 工程名 |
| 描述 | 可选 |
| **数据来源** | 必选：**连接 + 库**；PostgreSQL 另选**模式**；MySQL 等无独立模式层级。生成/探测默认作用域 |
| **工作连接** | 必选：**连接 + 库**；同样按库类型决定是否选模式。临时表与结果落库 |

**工作连接用途（唯一定义）：**

1. 执行过程中创建/写入**临时表**（治理中间结果等）；  
2. 落地**最终结果数据**（供弹窗查询与复用）；  
3. **重新执行**时在同一工作连接上更新/覆盖对应临时表与结果数据（按 run 策略清理旧临时对象）。

探测源表可来自空间内其它连接；工作流节点可绑定各自 `connectionId` 读源。临时表与结果表的 DDL/DML **只落在工程绑定的工作连接**上，方言取该连接元数据。

创建后工程卡片/详情展示工作连接名称；本期不支持随意更换工作连接（若更换须评审迁移策略，Out of Scope）。

| 操作 | 表现 |
|---|---|
| Chat 生成完成 | 「保存 / 不保存」；并提供**执行** |
| Chat 执行 | **执行日志写入会话窗口**；结束后出现「查看执行结果」，**点击弹窗**展示结果表 |
| 工作流页 | **执行**、**停止**；下侧展示执行日志；结果入口**点击弹窗**（与 Chat 相同弹窗） |
| 画布节点 | 前置节点成功/失败+原因；与日志一致 |

图形节点仅 **治理 SQL** 与 **查询（末）** 等业务节点，**不出现 EXPLAIN 节点**（语法合法性在生成阶段由服务端静态校验，不占画布节点）。

## 3. 本期范围

### 3.1 In Scope

| 能力 | 说明 |
|---|---|
| 工作空间门禁 / 工程目录 / 保存确认 | 同前 |
| 创建工程 | 名称 + 描述 + **必选工作连接**；用于临时表与结果落库、重跑结果 |
| Chat | 生成草稿；保存确认；**执行**；日志进会话；结果点击弹窗 |
| 工作流页 | 图形节点；**执行 / 停止**；下侧执行日志；结果弹窗 |
| 节点执行反馈 | 前置节点：成功或失败+原因；末节点：结果数据集（弹窗；数据在工作连接） |
| 探测 Tools / HITL / residency / 方言 / 审计 | 同前；审计含工作流执行与停止 |
| 碰库 | 全部经 sqlwork；按工作空间授权 |

### 3.2 Out of Scope

- 创建工程后随意更换工作连接及历史临时表迁移（本期不做）。
- 工作流页「导出」「带到 SQL 工作台」入口（本期不做）。
- 画布上的 EXPLAIN 节点。
- Agent **无人确认**自动跑完整工作流（须用户点执行；生成阶段探测 Tools 除外）。**例外：** [测评模式](./03-智能问数测评需求分析.md) 由测评编排自动保存并执行，不属于人工工作台路径。
- DeerFlow；askdata 直连目标库；云端明细抽样；MDM；工程下再套文件夹。

### 3.3 非目标澄清

| 误解 | 实际 |
|---|---|
| Chat 生成即落盘 | 须用户确认保存 |
| 工作流含 EXPLAIN 节点 | **无**；校验在生成侧，画布只有业务 SQL 节点 |
| 生成即执行 | **用户点执行**后才跑节点；Chat 与工作流页均可触发 |
| 工作连接 = 探测连接 | 工作连接专用于临时表与结果；源表可来自空间内其它已授权连接 |
| 模型自由调 sqlwork | **禁止**；须经 askdata **已声明 Tool**；SqlworkClient 仅 Handler/Runner 使用 |
| 模型自由选方言 | 以连接元数据为准 |

## 4. 角色与场景

| 角色 | 诉求 |
|---|---|
| 业务分析师 | Chat 生成 → 执行看结果；保存工作流复跑 |
| 数仓 / DBA | 看节点失败原因与控制台日志；补权后重试 |
| 平台管理员 | residency、授权、审计 |

| ID | 场景 | 期望 |
|---|---|---|
| S0 | 创建工程 | 必选工作连接；无连接不可创建 |
| S1 | 干净表 | 执行 → 临时/结果落工作连接 → 会话日志 → 结果弹窗 |
| S2 | 脏数据 | 治理中间结果进工作连接临时表；末结果落库 |
| S3 | 执行中取消 | 停止；已建临时表按策略清理或标记 |
| S4 | 某节点失败 | 会话日志 + 失败原因 |
| S5 | 重新执行 | 同工作连接上更新临时表与结果数据 |
| S6 | Chat 内执行 | 日志在会话；结果弹窗（读工作连接结果） |

## 5. 功能需求（摘要）

| 类 | 要点 | 优先级 |
|---|---|---|
| 创建工程 | 名称 + 描述 + **数据来源（连接/库/模式）** + **工作连接（连接/库/模式）**；模式随库类型 | P0 |
| 工作连接落库 | 临时表、最终结果、重跑覆盖/更新均在该连接的选定库/模式 | P0 |
| 目录 / Chat 生成保存 | 工程→工作流；草稿显式保存 | P0 |
| 执行 / 停止 | Chat 与工作流页均可执行；工作流页另有停止 | P0 |
| 图形节点 | 无 EXPLAIN；节点展示执行成功/失败（失败原因） | P0 |
| 执行反馈 | 会话内执行日志；结果点击弹窗；画布节点成功/失败 | P0 |
| **大模型运行监控** | 调用级耗时/Token/成败；图节点与 Tool 轨迹；与 TraceId/审计关联；云禁样本进 Trace | P0 |
| HITL / 方言 / sqlwork / 审计 | 同平台边界；工作连接需具备建临时表/写结果权限 | P0 |

### 5.1 大模型运行监控（专节）

与「会话里给用户看的执行日志」分流：前者是业务过程；**运行监控**面向运维/平台管理员，回答模型跑得怎样、贵不贵、卡在哪、失败为何。

| 维度 | 要采什么 | 谁看 |
|---|---|---|
| LLM 调用 | model、residency、latency、input/output tokens、成败、错误码；关联 `traceId / projectId / sessionId / userId` | 运维 / 管理员 |
| Agent / 图 | LangGraph（及 Deep Agents）节点名、进入/离开时间、路由结果、repair 轮次、HITL 等待时长 | 运维 / 研发 |
| Tool | Tool 名、耗时、成败；**不含**云链路样本正文 | 运维 / 研发 |
| 工作流 Run | 与既有 run 日志联动；生成阶段与执行阶段分 `phase=generate\|execute` | 运维 + 用户（用户侧已有会话/下侧日志） |
| 合规 | cloud：**禁止**抽样明细、明文样本进入第三方 Trace/日志；凭据永不入监控载荷 | 强制 |

**非目标：** 用第三方 SaaS Trace 默认上传全量 Prompt（含样本）；监控失败不阻断问数主流程。

**交付形态：**

| 数据 | 展示给谁看 | 在哪看 |
|---|---|---|
| Prometheus 指标 | 运维 / SRE | **Grafana**（刮取 `/metrics`）；内网运维看板 |
| `ask_llm_span` + summary | 有权限的审计/管理员 | **审计中心**侧栏新增菜单「**智能问数监控**」（与业务日志、SQL 操作日志并列） |
| 会话过程日志 / 结果弹窗 | 业务用户 | 智能问数工作台（不展示监控曲线） |

- 审计中心路由建议：`/audit/askdata-monitor`；权限码建议 `audit.askdata.view`（持有则显示该侧栏项；顶栏「审计日志」仍为任一 `audit.*.view`）。  
- 页面数据来自 `dbc-askdata` 管理查询 API（非 ES）；与业务/SQL 审计日志分流，同入口中心便于治理人员一站查看。  
- M1：`/metrics` + Grafana；span 落库。M3：审计中心菜单与列表页落地。  
- Chat 内不嵌 Prometheus / 监控页。

## 6. 主链路

```text
选空间 → 新建工程（名称 + 工作连接）→ Chat 生成草稿
  → 可选保存工作流子节点
  → 用户执行
  → 治理节点：在工作连接建/写临时表（经 sqlwork）
  → 末节点：结果写入工作连接结果表，弹窗可读
  → 重新执行：同连接更新临时表与结果
```

## 7. 拍板项

| # | 项 | 结论 |
|---|---|---|
| 1 | 创建工程 | **必选工作连接**；用于临时表、最终结果、重跑结果 |
| 2 | 画布操作 | **执行 / 停止**；不做导出、带到 SQL 工作台 |
| 3 | Chat | 提供**执行**；保存仍显式确认 |
| 4 | 节点类型 | **无 EXPLAIN 节点** |
| 5 | 执行反馈 | 会话日志；结果弹窗 |
| 6 | 触发 | 用户点击执行 |
| 7 | 碰库 | 只经 sqlwork；**模型不直调** meta/execute，只调 askdata 已声明 Tool |
| 8 | 平台库 | **PostgreSQL**；单独 schema **`askdata`** |
| 9 | 大模型监控 | 调用/图/Tool 可观测；TraceId 贯通；云禁样本进 Trace；监控失败不阻断 |
| 10 | 其它 | 目录两级、方言绑连接、LangGraph ± Deep Agents、不用 DeerFlow |

## 8. 验收标准

1. 创建工程未选工作连接不可提交。  
2. 执行产生的临时表与结果数据落在工程工作连接上（经 sqlwork）。  
3. 重新执行后结果可在弹窗看到更新后的数据。  
4. Chat 执行日志在会话；结果点击弹窗。  
5. 工作流页执行/停止；无导出、带到工作台。  
6. 无目标库直连；全链路可审计。  
7. 平台元数据表均在 PostgreSQL schema **`askdata`**（与工作连接临时表/结果表分离）。  
8. 单次问数生成可关联到 LLM 调用监控记录（耗时/Token/成败）与 Gateway `traceId`。  
9. `residency=cloud` 下监控/Trace 载荷无列抽样明细。

| 阶段 | 交付 |
|---|---|
| M1 | 工程（工作连接）+ Chat/执行 + 会话日志/结果弹窗 + LLM 埋点 + **/metrics 可刮取 + Grafana 看板（运维）** |

## 10. 小结

智能问数：平台元数据在 **PostgreSQL · schema `askdata`**；工作连接承载临时表与结果；会话日志/结果弹窗；LLM 可监控；碰库只经 sqlwork。
