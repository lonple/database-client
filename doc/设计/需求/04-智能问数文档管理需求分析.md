## 1. 要解决什么问题

智能问数左侧已有「问数空间」「知识库」。创建知识时，浏览器只接受 `.md` / `.markdown` / `.txt`（单文件 2MB），读成文本后作为知识正文交给 ada-memory。业务口径、制度、报表说明通常在 Word、PDF、Excel、HTML 里，今天只能人工转成 Markdown 再粘贴。

文档管理补的是这一段：

1. 在智能问数壳层增加菜单「文档管理」（与知识库并列，不进工作空间门禁，与现知识库列表同级）。
2. 上传 Word、PDF、Excel、HTML 或图片，服务端校验并转成 Markdown。
3. 对「源文件 + 转换结果」做列表、详情、替换、删除。
4. 用户确认后，把 Markdown 导入现有知识库，生成**草稿**；发布与向量同步仍走知识库现有门禁。

一句话：**智能问数 → 文档管理 → 上传 → 服务端转 Markdown → 列表里查看或修订 → 需要检索时再导入知识库草稿。**

「execl」按 **Excel** 理解。不接受可执行文件（`.exe` 等）。

## 2. 交互与信息架构

| 层级 | 内容 |
|---|---|
| 进入前 | 已登录且具备 `askdata.use`。不强制先选工作空间（与现「知识库」菜单一致）。文档仅创建人可见 |
| 顶栏 | 仍是平台一级菜单里的「智能问数」，不新增顶栏项 |
| 左侧 | 壳层二级菜单增加「文档管理」，与「问数空间」「知识库」并列 |
| 右侧 | 文档列表；空态说明可上传的格式。点名称进详情 |
| 弹窗 / 抽屉 | 「上传」打开上传弹窗；「删除」二次确认；「导入知识库」打开知识草稿表单（名称、简介、分类），成功后回到文档详情并给出知识库入口 |

### 2.1 列表

| 字段 | 必填 | 说明 |
|---|---|---|
| 名称 | 是 | 默认取文件名（去掉扩展名），可改 |
| 格式 | — | docx / pdf / xlsx / html |
| 转换状态 | — | 转换中 / 成功 / 失败 |
| 更新时间 | — | |
| 是否已导入知识库 | — | 只表示曾经导入过草稿，不表示已发布 |

| 操作 | 表现 |
|---|---|
| 上传成功且转换成功 | 列表出现一行，状态为成功，可进详情看 Markdown |
| 转换失败 | 行仍在，状态为失败，详情展示失败原因；可替换文件重试 |
| 空列表 | 提示尚无文档，并给出上传入口 |
| 无权限 | 菜单不可见（与问数其它页同一权限时，无单独隐藏） |

### 2.2 详情

| 区域 | 说明 |
|---|---|
| 源文件 | 可下载原件。页面不把 HTML/Office 当成本页脚本执行 |
| Markdown | 预览转换结果；允许改 Markdown 正文 |
| 状态条 | 若正文被人工改过，标明「与最近一次自动转换可能不一致」 |
| 导入知识库 | 用当前 Markdown 去创建知识草稿，不在本页发布 |

| 操作 | 表现 |
|---|---|
| 替换源文件 | 重新转换。若 Markdown 已被人工修改，先提示会用新转换结果覆盖正文 |
| 只改 Markdown | 保存正文，不回写 Word/PDF/Excel/HTML |
| 删除 | 二次确认后软删。不自动删除已经导入的知识 |

## 3. 本期范围

### 3.1 In Scope

| 能力 | 说明 |
|---|---|
| 菜单 | 智能问数壳层「文档管理」 |
| 上传 | `.docx`、`.pdf`、`.xlsx`、`.html` / `.htm`，以及 `.png`、`.jpg` / `.jpeg`、`.bmp`、`.tif` / `.tiff`、`.webp` |
| 转换 | 办公文档：正文、表格、标题层级，图片只抽出并引用。图片文件：识别图中文字和表格，保留标题、阅读顺序和表格结构。不还原流程图和复杂图 |
| 增删改查 | 列表、详情、改名称、改 Markdown、替换源文件、软删（二次确认） |
| 导入知识库 | 用户确认后，用当前 Markdown 创建知识库草稿 |

### 3.2 Out of Scope

- 可执行文件、脚本、压缩包、音视频、动图。
- 带宏的 Office（`.docm`、`.xlsm`、`.pptm`）。
- 旧版二进制 `.doc`、`.xls`（除非拍板纳入）。
- 识别办公文档**内部嵌图**、扫描版 PDF 里的文字。扫描版或抽不出文本层的 PDF 转换失败。
- 流程图、架构图、泳道图、统计图还原成结构或数据表。
- 视觉语言模型、云端识图。
- 抓取外链 HTML、打包网站、还原 HTML 里的图片与附件。
- 在线协同编辑 Word，或把 Markdown 回写成 Word/PDF。
- 上传后自动发布知识、自动写向量、自动参与问数检索。
- 新服务、浏览器里解析二进制、把原文件正文写入 ada-memory。
- 改问数工作台的生成/执行约束，或让文档转换去连目标库。

### 3.3 非目标澄清

| 误解 | 实际 |
|---|---|
| 上传后问数就能检索到 | 检索仍只命中知识库里**已发布**的内容。文档管理默认不发布 |
| 文档管理等于知识库 | 文档管理保存源文件和 Markdown；切片、发布、向量仍在知识库 |
| 浏览器直接读 Word/PDF | 转换在 `dbc-askdata`。浏览器只上传与预览结果 |
| 「execl」包含 exe | 只支持 Excel 工作簿。拒绝可执行文件 |
| 转换会改目标库 | 本能力不访问目标库 |
| Word/PDF 里贴了一张表格截图，转换会变成表 | 嵌在办公文档里的图片只引用，不读图。要识别图中的字和表，需把该图当作图片文件另传 |
| 上传一张流程图会得到节点和箭头 | 图片文件只出文字和表格。流程图上的字可能成段出现，不生成结构 |

## 4. 角色与场景

| 角色 | 诉求 |
|---|---|
| 业务分析师 / 知识维护人 | 把制度、口径、报表说明上传并转成 Markdown，再决定是否进入知识库 |
| 问数使用者 | 不在本菜单里问数；检索仍走已发布知识 |
| 平台管理员 | 权限沿用问数使用权限；删除与失败可追溯 |

| ID | 场景 | 期望 |
|---|---|---|
| S0 | 打开文档管理且无数据 | 空态 + 上传入口；不要求先选工作空间 |
| S1 | 上传 docx/pdf/xlsx/html 且能抽出文本 | 状态成功；详情能看到正文和表格；文档内图片以引用出现，嵌图中的字不进正文；能下载原件 |
| S1b | 上传含文字和表格的 png/jpg 等图片 | 状态成功；Markdown 含这些文字和表格，并保留标题与阅读顺序 |
| S2 | 上传不允许的类型，或文件损坏、加密、超限 | 不入库，或入库后状态失败并给出原因；列表不出现「成功」 |
| S3 | 扫描版 PDF，或 PDF 里的字只存在于页面图片中 | 状态失败。不把 PDF 页当图片文件去识别 |
| S4 | 替换源文件 | 重新转换；人工改过的 Markdown 被覆盖前有确认 |
| S5 | 只修改 Markdown | 保存成功，并标记与自动转换可能不一致 |
| S6 | 删除 | 二次确认；列表不再展示；已导入的知识仍在知识库 |
| S7 | 导入知识库 | 知识库出现草稿；文档详情能回到该知识。未发布前问数检索不命中 |
| S8 | 转换过程中服务重启或超时 | 状态落成失败或可重试，不长期停在「转换中」且无法操作 |

## 5. 功能需求

| 类 | 要点 | 优先级 |
|---|---|---|
| 菜单与列表 | 壳层入口；按名称、格式、状态筛选；分页 | P0 |
| 上传校验 | 扩展名与内容魔数一致；大小上限；拒绝宏与可执行文件 | P0 |
| 转换 | 办公文档与图片文件两条管线 → Markdown；失败原因可见；可重试 | P0 |
| 详情 | Markdown 预览、下载原件、改名称、改正文 | P0 |
| 删除 | 二次确认、软删 | P0 |
| 导入知识库 | 生成草稿，沿用现有分类（通用 / 元数据）与发布门禁 | P0 |
| 人工修订标记 | 正文偏离最近一次自动转换时可见 | P1 |
| 审计 | 上传、替换、删除、导入记到现有审计通道（谁、何时、哪份文档） | P1 |

权限：与知识库相同，使用 `askdata.use`。文档仅创建人可见（与 `ask_knowledge.owner_user_id` 一致）。空间内共享本期不做。

安全：

- HTML 只作转换输入。预览展示的是 Markdown 渲染结果，不把上传的 HTML 插入页面。
- 转换器不访问上传文件里的 URL（防止服务端请求伪造）。
- 原文件与 Markdown 按登录用户隔离；下载走问数服务鉴权，不发永久公开链接。

## 6. 主链路

1. 用户进入智能问数，点「文档管理」。
2. 上传文件。服务端校验通过后保存原件并开始转换。
3. 转换成功：详情展示 Markdown。转换失败：详情展示原因，用户可替换文件重试。
4. 用户可改名称、改 Markdown，或替换源文件。
5. 需要被问数检索时，用户点「导入知识库」，填写知识名称与简介（元数据类再选连接作用域），生成草稿。
6. 用户到知识库按现流程切片并发布后，问数才能命中。

分支：

- 取消上传：不产生文档记录。
- 删除：确认后软删，知识库记录保留。
- 导入时知识库校验失败（缺简介、元数据未选连接等）：文档与 Markdown 仍保留，提示到知识库规则，不回滚源文件。

## 7. 拍板项

### 7.1 已定（沿用平台，本篇不改）

| # | 项 | 结论 |
|---|---|---|
| 1 | 服务边界 | 不新增服务，不做浏览器解析，不把转换接到目标库 |
| 2 | 与知识库分工 | 文档管理产出 Markdown；检索、切片、发布、向量仍由现有知识库与 ada-memory 负责 |
| 3 | 发布门禁 | 导入知识库只产生草稿，不自动发布 |
| 4 | 删除 | 二次确认 |
| 5 | 可执行文件 | 拒绝 `.exe` 及同类可执行内容 |
| 6 | 嵌图与图片文件 | 办公文档内的图片只抽出并引用，不识别其内容。扫描版 PDF 失败。单独上传的图片文件要识别其中的文字和表格 |
| 7 | 转换引擎 | **Docling 两条管线**，见 §7.3。不引入第二套版面引擎，不用视觉模型，不调用云端识图 |
| 8 | Excel 形态 | 每个工作表一节表格，嵌在同一份 Markdown 中。不按工作表拆成多份文档 |

### 7.2 本期拍板（原待确认项）

| # | 项 | 结论 |
|---|---|---|
| 1 | 可见范围 | 仅创建人。不做工作空间共享 |
| 2 | 原文件存放 | 可配置本地目录（`DBC_ASKDATA_DOCUMENTS_DIR`），库里只留元数据与 Markdown。正式多副本应换成对象存储，见架构概要「已知不足」 |
| 3 | 转换执行 | 状态落库。本机/单进程用后台线程转换，超时 180 秒。启动时把遗留的「转换中」标为失败，可重试。不新建 Celery |
| 4 | 大小与表格 | 单文件 20MB。Markdown 正文上限 500_000 字符（与知识库正文一致）。xlsx 最多 20 个工作表，超出失败 |
| 5 | 旧版 Office | 不做 `.doc` / `.xls` |
| 6 | 替换源文件 | Markdown 被改过则覆盖前确认 |
| 7 | 删除与知识 | 删文档不删已导入知识 |

### 7.3 技术方案（已定）

转换在 `dbc-askdata` 进程内完成，引擎只用 **Docling**。按扩展名走两条管线，产物都是 Markdown。合并单元格用 HTML 表格嵌在 Markdown 中。字体、颜色、页眉页脚、文本框绕排、精确坐标不保留。

| 输入 | 管线 | 开关 | 产物 |
|---|---|---|---|
| `.docx`、`.pdf`、`.xlsx`、`.html`、`.htm` | 文档管线 | 关闭 OCR、配图描述、图片分类、图表抽取。PDF 打开表格结构。生成图片文件 | 正文、标题、列表、表格；图片仅引用 |
| `.png`、`.jpg`、`.jpeg`、`.bmp`、`.tif`、`.tiff`、`.webp` | 图片管线 | 打开 OCR 与表格结构。关闭图表抽取和视觉描述 | 按阅读顺序的文字、标题、表格 |

图片管线的 OCR 使用 Docling 的 **RapidOCR**（PaddleOCR 的 ONNX 模型，不安装 Paddle 运行时）。中英文文字和表格结构由这一条管线负责。不接视觉语言模型。

| 格式 | 规则 |
|---|---|
| docx | 接受。拒绝 docm。嵌图只引用 |
| pdf | 只读文本层和版面中的表。没有文本层则失败，不把页面送进图片管线 |
| xlsx | 每个工作表一节表格。拒绝 xlsm。图表当图片引用，不还原数据 |
| html | 单文件。去掉脚本后再转。不请求文件中的 URL；外链图片不下载 |
| 图片 | 无文字且无表格则失败。流程图只可能留下零散文字，不生成图形结构 |

不采用 MarkItDown（PDF 表格和图片弱）、Pandoc（盖不住 PDF 与 xlsx）、PyMuPDF 单独抽文本（复杂表不稳，且 AGPL）、MinerU/Marker（只强在 PDF，并常带识图）、云端文档智能（文件出域）。

PaddleOCR PP-StructureV3 不进入本期实现。它与 Docling 的版面、表格能力重叠，还要带上 Paddle 运行时。若验收样例里中文截图的表格明显不可用，只替换图片管线，文档管线不变。

模型在构建镜像时打入，运行时不从公网下载。CPU 执行，不为识图配备 GPU。镜像会明显大于现在的 `python:3.12-slim` 业务镜像。

存储：

| 数据 | 落点 |
|---|---|
| 名称、格式、状态、失败原因、创建人、与知识草稿的关联 | PostgreSQL schema `askdata` |
| Markdown 正文 | 同库文本字段 |
| 原文件与抽出的图片 | `DBC_ASKDATA_DOCUMENTS_DIR` 下按用户/文档分子目录 |

本机开发复用已安装的 CUDA PyTorch，再 `pip install docling`。Docker 镜像本期不强制打入 Docling；未安装时接口返回明确错误。不把 Pandoc、LibreOffice 或 Paddle 运行时装进默认镜像。

## 8. 验收标准

1. S0：侧栏能进入文档管理；无数据时有空态和上传。
2. S1：docx、pdf、xlsx、html 各一份可解析样例，Markdown 含主要文字和表格（Excel 为每个工作表一节、限定行内的单元格）；文档内图片以引用出现，嵌图中的文字不写入正文。
3. S1b：一张含标题、正文和表格的图片，Markdown 能按阅读顺序看到这些文字，表格仍是表。
4. S2：`.exe`、宏文件、超限文件、损坏文件不能显示为转换成功。
5. S3：无文本层的 PDF 失败，且不把该 PDF 送入图片管线。
6. S4、S5：替换与手工改 Markdown 的提示、覆盖、偏离标记与 §2.2 一致。
7. S6：删除有二次确认；删除后知识库原草稿仍在。
8. S7：导入后知识库为草稿；未发布时问数检索不因该文档命中。
9. S8：转换失败或中断后，用户能看到失败并能重试，不能只停在转换中。
