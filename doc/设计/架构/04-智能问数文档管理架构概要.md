---

## 1. 设计目标

选智能问数 → 文档管理 → 上传 → 服务端转 Markdown → 详情查看或修订 → 确认后导入知识库草稿。浏览器不解析二进制，不直连目标库。

---

## 2. 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 服务 | `dbc-askdata` | 不新增 Nacos 名与 URL 前缀 |
| 转换 | Docling；图片 OCR 用 RapidOCR | 本机复用已装 PyTorch（含 CUDA）；缺包时接口失败并打栈 |
| 平台库 | PostgreSQL schema `askdata` | 文档元数据与 Markdown；不是目标库表 |
| 原文件 | 本地目录 `DBC_ASKDATA_DOCUMENTS_DIR` | 多副本正式方案为对象存储，见 §6 |
| 知识 | 既有 ada-memory 旁路 | 仅用户确认导入后创建草稿 |

---

## 3. 逻辑架构

```text
dbc-front（文档管理列表/详情）
  → gateway /dbc-askdata/**
  → dbc-askdata
        ├─ Document API（鉴权 askdata.use）
        ├─ FileStore（本地目录；按 owner/id 隔离）
        ├─ DoclingConverter（文档管线 / 图片管线，线程池）
        └─ 导入时复用 Knowledge API → AdaMemoryClient
  目标库：不经过本能力
```

| 模块 | 职责 |
|---|---|
| Document API | 上传校验、列表、详情、替换、软删、下载、导入草稿 |
| FileStore | 写原件与抽出图片；读下载流 |
| DoclingConverter | 按扩展名选管线；超时；空文本判定 |
| Knowledge | 不在转换时自动发布 |

模型不可调用本 API。浏览器只走网关。

---

## 4. 边界

| 通道 | 受众 | 允许 |
|---|---|---|
| 文档管理页 | 有 `askdata.use` 的登录用户 | 只看自己的文档 |
| 知识库 | 同上 | 导入后的草稿；发布仍在知识库 |
| sqlwork / 目标库 | — | 本能力不调用 |
| 云端视觉 / 外网模型下载 | — | 转换时不访问 URL；模型应已在本机缓存 |

---

## 5. 主链路

1. 上传：魔数与扩展名、大小校验 → 落盘 → 状态 `QUEUED`。
2. 后台转换：`RUNNING` → 成功写 Markdown 与图片 → `SUCCESS`；失败写原因 → `FAILED`。
3. 用户改 Markdown 或替换源文件（改过则确认覆盖）。
4. 导入知识库：用户填名称与简介 → 创建**草稿**（`publish=false`）。

启动时把未结束的转换标为失败，允许重试。

---

## 6. 已知不足 / 非生产

平台尚无统一对象存储。本期原文落**单机可配置目录**。多副本、迁移节点时文件不共享。正式替代：S3/MinIO，表内存对象键。代码入口 `TODO(production):` 指向本节。

---

## 7. 小结

元数据与 Markdown 在 `askdata` schema；原件在本地目录；转换在 askdata 进程内用 Docling。不新增服务、不碰目标库。导入知识库仍须用户确认且只出草稿。
