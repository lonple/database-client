## 1. 设计目标

- 在 `dbc-askdata` 内扩展**测评域**（工程 / 用例 / 任务 / 跑批），与人工问数工作台隔离又共享生成与执行内核。
- 测评模式：**自动保存工作流 → 自动执行 → 按用例 HITL 策略续跑或拒补**。
- 比对：期望 SQL 经 sqlwork **现场执行** vs 问数结果；用例自带验证逻辑。
- 目标库访问仍**只经** `dbc-sqlwork`；平台元数据在 schema `askdata`。

---

## 2. 逻辑架构

```text
dbc-front
  选工作空间
    ├─ 问数工作台 ──► 现有 AskProject / Chat / 人工执行
    └─ 测评空间   ──► Eval UI（工程 / 用例 / 任务）
           │
           ▼
gateway（TraceId）→ dbc-askdata
  ├─ Eval API（工程、用例、任务、跑批控制）
  ├─ EvalRunner（编排）
  │     ├─ CaseExecutor
  │     │     ├─ 调用生成图（同 Chat 内核，测评 flag）
  │     │     ├─ AutoSave Workflow
  │     │     ├─ WorkflowRunner.execute
  │     │     └─ HitlPolicy（by case_key：补全 / 不补全）
  │     ├─ ExpectSqlExecutor（sqlwork 只读跑期望 SQL）
  │     └─ ResultComparer（按 compare_mode）
  ├─ 既有：LangGraph / ToolGateway / WorkflowRunner / SqlworkClient
  └─ 平台库 askdata.*（eval_* 表）
```

| 模块 | 职责 |
|---|---|
| Eval API | 工程 CRUD、用例分页、任务创建/列表/详情、触发跑批、停止 |
| EvalRunner | 任务级调度；并发上限；写任务进度 |
| CaseExecutor | 单用例：生成→自动保存→执行→HITL 循环 |
| HitlPolicy | `SUPPLEMENT`：按序推送 `hitl_replies`；`NO_SUPPLEMENT`：不推送，等待终态判定拒答 |
| ExpectSqlExecutor | 同源连接执行期望 SQL；超时/行数限制与问数对齐策略 |
| ResultComparer | `key_set` / `order_by` / `scalar` / `empty_or_refuse` |

## 3. 与问数内核的边界

| 能力 | 复用 | 测评特有 |
|---|---|---|
| NL→SQL / GOVERN 图 | 是 | `eval_mode=true`：跳过「请用户确认保存」 |
| WorkflowRunner | 是 | 由 EvalRunner 触发，非用户按钮 |
| HITL | 是 | 补话来源改为用例预置，而非会话人工 |
| AskProject | **不**把测评工程建成 AskProject | 可内部创建隐藏工作流归属或独立 `eval_run` 绑定 |
| 审计 / LLM span | 是 | span 带 `eval_task_id` / `case_key` |

**不**在测评路径开放模型直连 sqlwork；仍走声明制 Tool + Runner。

## 4. 数据与配置面

```text

  schema company          # 测评业务数据（可 DROP 重建）
  工作连接临时表/结果表   # 与问数相同前缀策略

平台库
  schema askdata
    eval_template / eval_project / eval_case / eval_task / eval_task_case / …

仓库文件（非库）
  scripts/demo-company/metadata/db-structure.md   # 交付风格表结构；部分枚举有说明
```

## 5. 跑批状态机（任务）

```text
PENDING → RUNNING → SUCCEEDED | FAILED | CANCELLED
              │
              └─ 逐条 CASE: PENDING → RUNNING → …
                    ├─ PASSED / PARTIAL_GE_80 / FAILED_COMPARE
                    ├─ ASK_FAILED
                    ├─ HITL_SUPPLEMENTED →（续）…
                    └─ REFUSED_OK / REFUSED_BAD   # 不补全子类
```

---

## 6. 安全与隔离

| 面 | 策略 |
|---|---|
| 工作空间 | 任务/工程强制 `workspace_id` + JWT 成员校验 |
| 连接 | 仅空间已授权连接；期望 SQL 与问数同源只读约束（期望 SQL 禁止写） |
| 期望 SQL | 服务端静态校验：单语句、只读；拒绝多语句/DDL/DML |
| 租户数据 | 测评结果集摘要可截断入库；全量以工作连接结果表为准（可选） |

---

## 7. 观测

- 任务进度：已完成/总数、当前 `case_key`。
- 复用 LLM span；增加评测维度标签。
- 失败必须打栈（对齐仓库异常日志规则）。

---

## 8. 小结

测评是 askdata 上的**编排与评分层**；生成/执行/碰库复用既有内核；模板引用 + 用例级验证 + HITL 三分策略构成可回归闭环。
