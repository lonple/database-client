> **文档定位**：产品整体技术架构、网络架构与重点技术概要。

## 1. 总体技术架构

### 1.1 模块化原则

- **一个业务域 = 一个可独立部署的 Spring Boot 应用 = 一个 Nacos 服务名**。
- 目录名、`spring.application.name`、Gateway 路径第一段三者一致。
- Java 根包：`com.lyj.dbc.{服务短名}.{功能模块}`（见 [../../规范/02-模块化规范.md](../../规范/02-模块化规范.md)）。
- 前端唯一应用 `dbc-front`：`src/common/` + `src/modules/{域}/`。
- 公共能力可抽 `dbc-common` / `dbc-client` 依赖包（已部分落地 client）。

### 1.2 仓库与服务

```
database-client/
  dbc-front/ dbc-gateway/ dbc-usercenter/
  dbc-manage/ dbc-sqlwork/ dbc-audit/
  dbc-client/          # 跨服务客户端依赖
  doc/
```

| 服务 | 端口（本地） | 职责 |
| --- | --- | --- |
| Nacos | 8000 / 控制台 8001 | 发现 |
| gateway | 8003 | 路由 |
| usercenter | 8004 HTTP / 8044 mTLS | IAM、代签 |
| front(dev) | 8005 | Vite |
| manage | 8006 | 管控面 |
| sqlwork | 8007 | 执行面 |
| audit | 8008 / mTLS 8048 | 审计（ES 写入与查询） |

开发：Vite 将 `/dbc-*` 代理到 gateway。生产：Nginx 托管前端，`/dbc-**` 进 gateway。详见 [../详细设计/05-网关与注册中心.md](../详细设计/05-网关与注册中心.md)、[../../运维/01-本地启动说明.md](../../运维/01-本地启动说明.md)。

### 1.3 技术选型

| 层 | 选择 |
| --- | --- |
| 业务服务 | Java 21 + Spring Boot 3.3.x + MyBatis-Plus + Gradle |
| 平台库 | PostgreSQL 16；按服务 schema（`usercenter` / `manage` / …） |
| 审计存储 | Elasticsearch（**仅 dbc-audit 写入**） |
| 平台连接池 | Druid + Flyway |
| 目标库连接池 | 按 connectionId 动态 Druid（**仅 sqlwork**） |
| SQL 解析 | Druid SQL Parser（按目标库方言） |
| 认证 | JWT HS256；usercenter 签发 |
| 密码 | 用户 BCrypt；连接凭证 AES-GCM（manage-kek） |
| 前端 | Vue 3 + TS + Vite + Ant Design Vue 4 + Pinia + Vue Router |
| 网关 / 发现 | Spring Cloud Gateway + Nacos |

### 1.4 服务边界

| 服务 | 职责 |
| --- | --- |
| gateway | 路由；（可选）限流；不注册业务 API |
| usercenter | 登录、JWT、用户/角色/部门、功能权限、应用 mTLS |
| manage | 数据资产、工作空间授权、全局管控策略；**不直连目标库** |
| sqlwork | SQL 工作台；**凡目标库访问只经此服务** |
| audit | SQL/业务审计 ingest（仅本服务写 ES）与查询 |

```
dbc-front → dbc-gateway → dbc-usercenter / dbc-manage / dbc-sqlwork / dbc-audit
```

## 2. 网络架构

```
浏览器
  → Vite :8005 / Nginx :80
       ├─ /                 → 静态前端
       └─ /dbc-{module}/**  → gateway :8003
                                → Nacos lb://服务名
                                    ├─ usercenter :8004
                                    ├─ manage :8006
                                    ├─ sqlwork :8007
                                    └─ audit :8008
                              PostgreSQL（平台库）
                              目标库 ← 仅 sqlwork
```

| 通道 | 协议 | 用途 |
| --- | --- | --- |
| 浏览器 → Gateway → 业务 | HTTP + JWT | 用户 API |
| 业务 → usercenter `:8044` | HTTPS + mTLS | 申请/代签/心跳/公钥 |
| 业务 A → B `/inner/**` | HTTP + ECDSA 应用层签名 | 凭证、鉴权、元数据等 |

密钥与证书不进 Git / Nacos。细则：[../详细设计/04-服务间请求签名.md](../详细设计/04-服务间请求签名.md)。

## 3. 重点技术概要

### 3.1 认证与功能权限

1. `POST /dbc-usercenter/auth/login` → JWT；`Authorization: Bearer`。
2. `/auth/me` 返回角色与权限码；401 回登录。
3. 权限码 `{服务}.{功能}.{view|operate}`；跨服务启动注册。
4. 前端菜单按权限过滤。

### 3.2 部门数据范围

角色绑定 `ALL` / `DEPT_AND_CHILDREN` / `DEPT_ONLY` / `CUSTOM`；多角色并集。manage 资产按 `dept_id` ∩ scope 过滤。

### 3.3 两类库与连接池

| 类型 | 技术 | 落点 |
| --- | --- | --- |
| 平台库 | 默认 DataSource + Druid + Flyway | 各服务 schema |
| 目标库 | 动态 Druid（connectionId） | **仅 sqlwork** |

- 单池 `maximumPoolSize` 建议 5～15；可加全局总闸。
- 密码解密后仅内存建池，不落日志。
- 方言：`DbDialect` SPI（探活、切库、标识符、元数据）；禁止业务路径按库类型 if/else 堆砌。
- 平台结构：Flyway；用户脚本仓库为产品能力（P1+），与 Flyway 无关。
- 解析：Druid SQL Parser（按 `DbType` 方言）；执行管道 Parse → 空间鉴权 → 全局策略 → Execute → 日志/Audit。
- 会话：自动提交走池；`BEGIN` 后独占连接直至提交/回滚/超时（见 sqlwork 详设）。

### 3.4 SQL 执行管道与元数据

```
Parse（Druid 批拆分）→ 空间成员/资产鉴权(manage)
  → 全局管控策略(manage：阻断/二次鉴权/告警)
  → Execute（池或会话租约）→ 执行日志 / Audit
```

- **已取消** pipeline 中的 Risk/高危步骤；风控模块后置。
- 元数据方案 A：工作台 → sqlwork；资产「指定表」→ manage → sqlwork `/inner/meta/**`。

### 3.5 前端信息架构

顶栏：**首页 → SQL 工作台 → 权限管控 → 资产管理 → 用户中心 → 系统管理**。  
- 权限管控侧栏：公司域为全局管控、工作空间授权；个人域仅工作空间授权。  
- 资产管理侧栏：实例、连接（域切换 +「（个人）」文案，不并列「我的*」菜单）。  
- 右上角用户名下拉含「个人空间」；个人域顶栏有「退出个人空间」明显出口。  
详见 [../详细设计/06-前端与界面设计.md](../详细设计/06-前端与界面设计.md)。

## 4. 实现顺序（架构视角）

1. 权限码迁移 + 菜单「权限管控」（已落地）  
2. 全局管控 CRUD + 执行期裁决 / 二次鉴权 ticket  
3. sqlwork 批执行 + 日志 + 多结果 Tab（已落地主干）  
4. **个人空间**：域切换 UI + 个人工作空间/资产隔离 + 挂载校验 + `DATA_OPERATOR`  
5. 会话窗口 + 手动事务租约  
6. audit：`dbc-audit` + `dbc-audit-client` + ES；SQL/业务日志页
