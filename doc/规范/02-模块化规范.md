# 02 模块化规范

> 前后端统一按 **业务域** 划分模块；后端一个域对应一个微服务，前端单应用多模块聚合。

## 1. 命名约定总览

| 维度 | 约定 | 示例 |
| --- | --- | --- |
| 仓库目录 / Gradle 工程 | `dbc-{域}` | `dbc-usercenter`、`dbc-gateway` |
| Nacos 服务名 | 同目录名 | `dbc-usercenter` |
| Gateway 路由前缀 | 同服务名 | `/dbc-usercenter/**` |
| 后端 Java 根包 | `com.lyj.dbc.{服务短名}.{功能模块}` | `com.lyj.dbc.usercenter.auth` |
| 前端模块目录 | `src/modules/{域-kebab}` | `modules/user-center` |
| 数据库表前缀 | `t_{域}_{实体}` | `t_usercenter_user` |

**服务短名**：去掉 `dbc-` 前缀后的部分，如 `usercenter`、`gateway`、`asset`。

---

## 2. 后端包结构

### 2.1 规则

```
com.lyj.dbc.{服务短名}.{功能模块}[.{子层}]
```

- **服务短名**：与微服务一一对应（`usercenter`、`gateway` …）。
- **功能模块**：按业务能力划分（`auth`、`user`、`role`、`config`、`common` …）。
- **子层**（按需）：`entity`、`dto`、`vo`、`mapper`、`controller` 等保持现有分层习惯。

### 2.2 已落地示例

**dbc-gateway**

```
com.lyj.dbc.gateway
  GatewayApplication.java
```

**dbc-usercenter**

```
com.lyj.dbc.usercenter
  UserCenterApplication.java
  common/          # ApiResponse、分页、异常
  config/          # MyBatis、JWT、CORS
  security/        # JWT 过滤器、Security 配置
  auth/            # 登录
    dto/
    AuthController / AuthService
  user/
    entity/ dto/ vo/ mapper/
    UserController / UserService
  role/
    entity/ vo/ mapper/
    RoleController / RoleService
```

### 2.3 后续微服务（已定规划）

| 工程 | 包根 | 说明 |
| --- | --- | --- |
| `dbc-manage` | `com.lyj.dbc.manage` | 数据资产、数据权限、安全策略（管控面） |
| `dbc-sqlwork` | `com.lyj.dbc.sqlwork` | SQL 工作台；目标库唯一出口（执行面） |
| `dbc-audit` | `com.lyj.dbc.audit` | SQL 执行审计 + 业务操作审计 |

详见 [../设计/需求/01-需求设计.md](../设计/需求/01-需求设计.md)、[../设计/架构/01-架构设计.md](../设计/架构/01-架构设计.md)。

公共能力（统一响应、异常、JWT 工具等）可后续抽 **`dbc-common`** Maven/Gradle 依赖，一期各服务内 `common` 包可少量复制。

## 3. 前端模块结构

### 3.1 原则

- **单前端应用**（`dbc-front`），按业务域拆 **`modules/`**，路由与 API 随模块走。
- **`common/`** 放跨模块复用：HTTP 客户端、通用类型、全局样式、后续可抽通用组件。
- 模块内自包含：`api/`、`stores/`、`views/`、`routes.ts`；登录态等可暂放用户中心，后续上提 `common`。

### 3.2 目录

```
dbc-front/src/
  common/
    api/           # http.ts、通用 ApiResponse / PageResult
    styles/        # main.css
  modules/
    user-center/   # 用户中心（对接 dbc-usercenter）
      constants.ts # USER_CENTER_BASE = '/dbc-usercenter'
      api/
      stores/
      views/
      routes.ts    # 路由 + 侧栏菜单配置
    system/        # 系统管理（应用管理等，对接 usercenter）
    manage/        # 数据管控（对接 dbc-manage）
    sqlwork/       # SQL 工作台（对接 dbc-sqlwork）
    audit/         # 审计中心（对接 dbc-audit）
  layouts/         # 工作台壳层
  router/          # 聚合各模块 routes
  App.vue
  main.ts
```

### 3.3 路由聚合

`router/index.ts` 合并各模块导出：

```ts
import { userCenterRoutes } from '@/modules/user-center/routes'
import { systemRoutes } from '@/modules/system/routes'
import { manageRoutes } from '@/modules/manage/routes'
import { sqlworkRoutes } from '@/modules/sqlwork/routes'
import { auditRoutes } from '@/modules/audit/routes'

routes: [
  { path: '/', redirect: '/home' },
  ...userCenterRoutes,
  ...systemRoutes,
  ...manageRoutes,
  ...sqlworkRoutes,
  ...auditRoutes,
]
```

新增业务域时：**新建 `modules/{域}` → 实现 `routes.ts` → 在 router 中 spread 注册 → Gateway 增加对应 `/dbc-{域}/**` 代理**。

### 3.4 API 路径

前端请求统一经 Gateway，模块内 constants 定义前缀：

```ts
export const USER_CENTER_BASE = '/dbc-usercenter'
export const MANAGE_BASE = '/dbc-manage'
export const SQLWORK_BASE = '/dbc-sqlwork'
export const AUDIT_BASE = '/dbc-audit'
```

Vite 开发代理：`/dbc-usercenter` → `http://127.0.0.1:8003`（Gateway）。

## 5. 新增模块检查清单

**后端**

1. 新建 Gradle 子工程 `dbc-{域}`，`group = "com.lyj.dbc"`。
2. 包名 `com.lyj.dbc.{域短名}.*`，按功能分子包。
3. `spring.application.name = dbc-{域}`，注册 Nacos，分配端口（见运维文档）。
4. Gateway 增加 `Path=/dbc-{域}/**` + `StripPrefix=1`。
5. Flyway 脚本、表名 `t_{域}_*`。

**前端**

1. 新建 `src/modules/{域-kebab}/`，含 `routes.ts`、`constants.ts`。
2. 在 `router/index.ts` 注册路由。
3. `vite.config.ts` 增加 `/dbc-{域}` 代理（如需要）。
4. 顶栏一级菜单扩展（多域时）。
