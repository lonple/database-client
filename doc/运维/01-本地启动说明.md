# 07 本地启动说明

> 基础设施与前后端 Docker 部署见 [02-Docker桌面部署手册.md](./02-Docker桌面部署手册.md)。  
> **一键部署 / 停止**（仓库根执行）：`.\scripts\docker-deploy.cmd`、`.\scripts\docker-stop.cmd`

## 端口一览（避免冲突，业务端口自增）

| 用途 | 端口 |
| --- | --- |
| Nacos 服务发现 / Open API | `8000` |
| Nacos 控制台 | `8001` |
| `dbc-gateway` | `8003` |
| `dbc-usercenter` | `8004` |
| `dbc-front`（Vite） | `8005` |
| `dbc-manage` | `8006` |
| `dbc-sqlwork` | `8007` |
| `dbc-audit` | `8008`（查询 HTTP）；mTLS ingest `8048` |
| 后续新服务 | `8009`… 依次递增 |
| PostgreSQL | `5432` |
| Redis | `6379` |
| Elasticsearch（审计） | `9200`（仅 `dbc-audit` 直连） |
| 用户中心 mTLS | `8044`（HTTPS，强制客户端证书） |

约定：业务应用从 **8003** 起自增，不要占用 8000 / 8001。

## 依赖

- JDK 21+
- 本地 Nacos：`127.0.0.1:8000`（控制台 `http://127.0.0.1:8001`）；单机模式启动见下方
- PostgreSQL：`127.0.0.1:5432`，库 `postgres`，账号 `postgres` / 密码 `root`；**schema 按服务划分**（`usercenter` / `manage` / …），Flyway 启动时自动创建  
- Elasticsearch：`127.0.0.1:9200`（**审计必依赖**；仅 `dbc-audit` 写入）。未启动时审计查询会返回 503 提示。
  - 有 Docker：`docker compose -f deploy/docker-compose.yml up -d elasticsearch`
  - 无 Docker：本机安装 [Elasticsearch 8.x](https://www.elastic.co/downloads/elasticsearch) 单节点，关闭安全或按 `DBC_ES_URIS` 配置；启动后访问 `http://127.0.0.1:9200` 应有 JSON 响应。
- **开发期 Flyway**：各服务仅保留 `V1__init.sql` 一份全量脚本；清库重跑即可。稳定后再拆增量版本号。
- **改了 `V1__init.sql` 后**：需 drop 对应 schema（如 `DROP SCHEMA manage CASCADE; DROP SCHEMA usercenter CASCADE;`）再重启服务，否则 Flyway 不会重跑。个人空间相关字段（`space_type` / `owner_scope`）已写入 manage 的 `V1`；审计权限码与应用 `dbc-audit` 已写入 usercenter 的 `V1`。
- Redis：`127.0.0.1:6379`（服务签名 nonce；可用 `DBC_REDIS_HOST` / `DBC_REDIS_PORT` / `DBC_REDIS_PASSWORD`）
- Node.js 18+
- **dbc-client（本机 mavenLocal）**：各业务服务默认 `dbc.client.composite=false`，从 mavenLocal 解析 `com.lyj.dbc:*-client:0.1.0`。**首次克隆或改了 `dbc-client` 源码后**先发布一次，再启服务（否则缺依赖或仍走 includeBuild 会锁 jar）：

```powershell
cd e:\workspace\database-client\scripts
.\publish-dbc-client.ps1
# 或：cd dbc-client ; .\gradlew.bat publishToMavenLocal
```

Windows 上若多个服务同时用 `includeBuild("../dbc-client")`，Gradle 会试图覆盖已被其它 JVM 占用的 `build\libs\*.jar`，报 `Unable to delete file ... dbc-*-client-0.1.0.jar`。保持 `composite=false` + mavenLocal 即可单服务启停。需要联调 client 源码时再临时设 `dbc.client.composite=true`，并先停掉占用该 jar 的其它进程。

### 审计 ES 索引重置（映射变更）

开发环境映射不兼容时（如 `can't merge … details.changes.after`），直接删索引后重启 `dbc-audit`（会注册 `…-template-v2`）：

```powershell
curl.exe -s -X DELETE "http://127.0.0.1:9200/dev-dbc-audit-biz-2026.09"
curl.exe -s -X DELETE "http://127.0.0.1:9200/dev-dbc-audit-sql-2026.09"
# 先用 _cat/indices/dev-dbc-audit* 查看实际索引名；ES 9 默认禁止通配删除
```

### Nacos 单机启动（Windows）

在 Nacos 安装目录的 `bin` 下执行：

```cmd
startup.cmd -m standalone
```

需保证主端口/控制台为本约定的 `8000` / `8001`（在 Nacos 配置中改，勿与业务端口冲突）。控制台：`http://127.0.0.1:8001`。

## 密钥与证书（`secrets/`）

仓库根下 `secrets/`（默认 `dbc.secrets.dir=secrets`，工作目录为仓库根）：

| 文件 | 说明 |
| --- | --- |
| `svc-kek.txt` | 加密库内签名私钥 |
| `jwt-secret.txt` | 用户登录 JWT 密钥 |
| `{clientId}.instance` | 本机实例 ID（启动自动生成） |
| `mtls/**` | CA、信任库、服务端证书、各应用客户端 p12 |

首次启动用户中心会自动生成缺失的 CA/信任库/服务端/内置应用客户端证书。已 gitignore。  
代签/申请密钥：usercenter **自身**走本机回环 `https://127.0.0.1:{mtls-port}`（不经 Nacos）；**其它服务**调 usercenter 用 `discovery://dbc-usercenter`。  
详见 [../设计/详细设计/04-服务间请求签名.md](../设计/详细设计/04-服务间请求签名.md)、[../设计/详细设计/05-网关与注册中心.md](../设计/详细设计/05-网关与注册中心.md)。

> IDEA 运行请使用仓库内 Run Configuration（工作目录 `$PROJECT_DIR$`）；`gradlew bootRun` 已固定工作目录为仓库根。若曾把密钥写到仓库外的 `../secrets`，请移回仓库根 `secrets/`。

## 启动顺序

```powershell
# 1. 基础设施：PostgreSQL、Redis、Elasticsearch；Nacos 单机（在 Nacos 的 bin 目录）
#    startup.cmd -m standalone
#    （可选）docker compose -f deploy/docker-compose.yml up -d
#    （postgres/root，库 postgres；ES :9200；Nacos 发现 :8000，控制台 :8001）

# 2. 用户中心 :8004（schema=usercenter；Flyway 自动建 schema；会为已登记应用补客户端证书，含 dbc-audit）
cd e:\workspace\database-client\dbc-usercenter
.\gradlew.bat bootRun

# 3. 资产管理 :8006（可与 usercenter 并行；权限注册失败只打日志，不拦启动）
cd e:\workspace\database-client\dbc-manage
.\gradlew.bat bootRun

# 4. SQL 工作台 :8007
cd e:\workspace\database-client\dbc-sqlwork
.\gradlew.bat bootRun

# 5. 审计 :8008（依赖 ES :9200；mTLS ingest :8048）
cd e:\workspace\database-client\dbc-audit
.\gradlew.bat bootRun

# 6. 网关 :8003
cd e:\workspace\database-client\dbc-gateway
.\gradlew.bat bootRun

# 7. 前端 :8005
cd e:\workspace\database-client\dbc-front
npm.cmd install
npm.cmd run dev
```

浏览器打开：`http://127.0.0.1:8005`  
账号：`admin` / `admin`  
Nacos 控制台：`http://127.0.0.1:8001`  
登录 API 示例：`POST http://127.0.0.1:8003/dbc-usercenter/auth/login`

### PowerShell 下 `npm` 报「禁止运行脚本」

Windows PowerShell 默认会拦截 `npm.ps1`，报错类似：`无法加载文件 …\npm.ps1，因为在此系统上禁止运行脚本`。任选其一：

1. **推荐（不改策略）**：用 `npm.cmd`，如上启动命令。
2. **当前用户放开脚本**（一次生效，之后可直接写 `npm`）：
   ```powershell
   Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
   ```
3. 终端改用 **CMD**，再执行 `npm install` / `npm run dev`。

## IDEA 运行说明

包名迁移后主类为：

- Gateway：`com.lyj.dbc.gateway.GatewayApplication`
- UserCenter：`com.lyj.dbc.usercenter.UserCenterApplication`
- Manage：`com.lyj.dbc.manage.ManageApplication`（Gradle 任务 `bootRun`，工程目录 `dbc-manage`）
- Sqlwork：`com.lyj.dbc.sqlwork.SqlworkApplication`（Gradle `bootRun`，工程目录 `dbc-sqlwork`）
- Audit：`com.lyj.dbc.audit.AuditApplication`（Gradle `bootRun`，工程目录 `dbc-audit`；需 ES）

仓库为**多独立 Gradle 工程**（非单一 root 多模块）。在 IDEA 中需把 `dbc-gateway` / `dbc-usercenter` / `dbc-manage` / `dbc-sqlwork` / `dbc-audit` 都链进 Gradle（见 `.idea/gradle.xml`）。若侧栏看不到某工程：

1. Gradle 工具窗 → 加号 / Link Gradle Project → 选对应 `build.gradle.kts`
2. 或 **Reload All Gradle Projects**
3. 再运行配置 **ManageApplication** / **SqlworkApplication**（sqlwork 为对该工程执行 `bootRun`）

工作目录须为仓库根（`bootRun` 已固定），以便读取 `secrets/`。

## 文件编码

全仓库文本文件统一 **UTF-8 无 BOM**（见根目录 `.editorconfig`、`.idea/encodings.xml`）。

## 数据库重置（规范改建表后）

若本地需重建 IAM（含改用 `usercenter` schema），可：

```sql
DROP SCHEMA IF EXISTS usercenter CASCADE;
-- 若仍残留旧 public 表也可按需 DROP；开发环境不必做 public→usercenter 数据迁移
```

然后重启 `dbc-usercenter`，Flyway 会自动创建 `usercenter` schema 并执行迁移。

## 目标库联调约定（sqlwork）

对自行配置的 PostgreSQL 等目标库做写/DDL 测试时，**请只操作 `public` schema**，不要改其它业务模式中的数据。对象浏览仍可展示全部 schema；产品不按「仅 public」硬拦截（见设计 14）。
