# 07 本地启动说明

> 基础设施与前后端 Docker 部署见 [02-Docker桌面部署手册.md](./02-Docker桌面部署手册.md)。  
> **一键部署 / 停止**（仓库根执行）：`.\scripts\docker-deploy.cmd`、`.\scripts\docker-stop.cmd`  
> 只重建一个服务：`.\scripts\docker-deploy.cmd -Build askdata`（短名：`askdata` / `sqlwork` / `front` / `gateway` / `usercenter`（`uc`） / `manage` / `audit`）。对照表见 [02-Docker桌面部署手册](./02-Docker桌面部署手册.md) §0。

## 端口一览（避免冲突，业务端口自增）

| 用途 | 端口 |
| --- | --- |
| Nacos 服务发现 / Open API | `8000` |
| Nacos 控制台 | `8001` |
| `dbc-gateway` | `8003` |
| `dbc-usercenter` | `8004` |
| `dbc-front`（Vite） | `8005` |
| `dbc-manage` | `8006` |
| `dbc-sqlwork` | `8007` |
| `dbc-audit` | `8008`（查询 HTTP）；mTLS ingest `8048` |
| `dbc-askdata` | `8009`（Python / FastAPI） |
| 后续新服务 | `8010`… 依次递增 |
| PostgreSQL | `5432` |
| Redis | `6379` |
| Elasticsearch（审计） | `9200`（仅 `dbc-audit` 直连） |
| 用户中心 mTLS | `8044`（HTTPS，强制客户端证书） |

约定：业务应用从 **8003** 起自增，不要占用 8000 / 8001。

## 依赖

- JDK 21+
- 本地 Nacos：`127.0.0.1:8000`（控制台 `http://127.0.0.1:8001`）；单机模式启动见下方
- PostgreSQL：`127.0.0.1:5432`，库 `postgres`，账号 `postgres` / 密码 `root`；**schema 按服务划分**（`usercenter` / `manage` / …），Flyway 启动时自动创建  
- Elasticsearch：`127.0.0.1:9200`（**审计必依赖**；仅 `dbc-audit` 写入）。未启动时审计查询会返回 503 提示。
  - 有 Docker：`docker compose -f deploy/docker-compose.yml up -d elasticsearch`
  - 无 Docker：本机安装 [Elasticsearch 8.x](https://www.elastic.co/downloads/elasticsearch) 单节点，关闭安全或按 `DBC_ES_URIS` 配置；启动后访问 `http://127.0.0.1:9200` 应有 JSON 响应。
- **开发期 Flyway**：各服务仅保留 `V1__init.sql` 一份全量脚本；清库重跑即可。稳定后再拆增量版本号。
- **改了 `V1__init.sql` 后**：需 drop 对应 schema（如 `DROP SCHEMA manage CASCADE; DROP SCHEMA usercenter CASCADE;`）再重启服务，否则 Flyway 不会重跑。个人空间相关字段（`space_type` / `owner_scope`）已写入 manage 的 `V1`；审计权限码与应用 `dbc-audit` 已写入 usercenter 的 `V1`。
- Redis：`127.0.0.1:6379`（服务签名 nonce、JWT jti 拒绝名单、网关验 access；可用 `DBC_REDIS_HOST` / `DBC_REDIS_PORT` / `DBC_REDIS_PASSWORD`）
- 浏览器会话：access 仅前端内存；refresh/csrf 为 Cookie。网关会验 Bearer access（login/refresh/logout 除外）。详见 [架构设计 §3.1](../设计/架构/01-架构设计.md)。
- Node.js 18+
- **dbc-client（本机 mavenLocal）**：各业务服务默认 `dbc.client.composite=false`，从 mavenLocal 解析 `com.lyj.dbc:*-client:0.1.0`。**首次克隆或改了 `dbc-client` 源码后**先发布一次，再启服务（否则缺依赖或仍走 includeBuild 会锁 jar）：

```powershell
cd e:\workspace\agent-project\database-client\scripts
.\publish-dbc-client.ps1
# 或：cd dbc-client ; .\gradlew.bat publishToMavenLocal
```

Windows 上若多个服务同时用 `includeBuild("../dbc-client")`，Gradle 会试图覆盖已被其它 JVM 占用的 `build\libs\*.jar`，报 `Unable to delete file ... dbc-*-client-0.1.0.jar`。保持 `composite=false` + mavenLocal 即可单服务启停。需要联调 client 源码时再临时设 `dbc.client.composite=true`，并先停掉占用该 jar 的其它进程。

### 审计 ES 索引重置（映射变更）

开发环境映射不兼容时（如 `can't merge … details.changes.after`），直接删索引后重启 `dbc-audit`（会注册 `…-template-v2`）：

```powershell
curl.exe -s -X DELETE "http://127.0.0.1:9200/dev-dbc-audit-biz-2026.09"
curl.exe -s -X DELETE "http://127.0.0.1:9200/dev-dbc-audit-sql-2026.09"
# 先用 _cat/indices/dev-dbc-audit* 查看实际索引名；ES 9 默认禁止通配删除
```

### Nacos 单机启动（Windows）

在 Nacos 安装目录的 `bin` 下执行：

```cmd
startup.cmd -m standalone
```

需保证主端口/控制台为本约定的 `8000` / `8001`（在 Nacos 配置中改，勿与业务端口冲突）。控制台：`http://127.0.0.1:8001`。

## 密钥与证书（`secrets/`）

仓库根下 `secrets/`（默认 `dbc.secrets.dir=secrets`，工作目录为仓库根）：

| 文件 | 说明 |
| --- | --- |
| `svc-kek.txt` | 加密库内签名私钥 |
| `jwt-secret.txt` | 用户登录 JWT 密钥 |
| `{clientId}.instance` | 本机实例 ID（启动自动生成） |
| `mtls/**` | CA、信任库、服务端证书、各应用客户端 p12 |

首次启动用户中心会自动生成缺失的 CA/信任库/服务端/内置应用客户端证书。已 gitignore。  
代签/申请密钥：usercenter **自身**走本机回环 `https://127.0.0.1:{mtls-port}`（不经 Nacos）；**其它服务**调 usercenter 用 `discovery://dbc-usercenter`。  
详见 [../设计/详细设计/04-服务间请求签名.md](../设计/详细设计/04-服务间请求签名.md)、[../设计/详细设计/05-网关与注册中心.md](../设计/详细设计/05-网关与注册中心.md)。

> IDEA 运行请使用仓库内 Run Configuration（工作目录 `$PROJECT_DIR$`）；`gradlew bootRun` 已固定工作目录为仓库根。若曾把密钥写到仓库外的 `../secrets`，请移回仓库根 `secrets/`。

## 启动顺序

### 0. 基础设施（须先就绪）

```powershell
# PostgreSQL、Redis、Elasticsearch；Nacos 单机（在 Nacos 的 bin 目录）
#   startup.cmd -m standalone
# （可选）docker compose -f deploy/docker-compose.yml up -d
# postgres/root，库 postgres；ES :9200；Nacos 发现 :8000，控制台 :8001
```

本机一键脚本**不**启停上述中间件。

### 1. 一键本地启动（推荐）

仓库根执行。对**本次选中的模块**会**先停再启**：按端口杀掉监听进程（含 usercenter mTLS `8044`、audit ingest `8048`、askdata debugpy `5678`），并尝试关闭此前脚本打开的同名控制台（窗口标题 `dbc-*`），再按依赖顺序启动。

**用法约定**

| 写法 | 行为 |
| --- | --- |
| `.\scripts\local-start.cmd` | 全部服务先停再启 |
| `.\scripts\local-start.cmd askdata front` | 仅指定服务先停再启（**空格**分隔）；**自动带上 `gateway`**（前端经 `:8003` 代理，漏网关会登录 500） |
| 默认 | **前台汇总日志**：服务输出写入 `scripts/.local-run/logs/*.log`，脚本轮询并打印到当前窗口（行前缀 `[模块名]`）；`Ctrl+C` 停本次选中服务 |
| `-Background` | **后台多窗口**：每个服务独立控制台，启动脚本退出 |
| `-Skip gateway` | 显式不启网关（一般不要） |

| 模块短名 | 目录 | 端口 |
| --- | --- | --- |
| `usercenter`（`uc`） | `dbc-usercenter` | `8004`（mTLS `8044`） |
| `manage` | `dbc-manage` | `8006` |
| `sqlwork` | `dbc-sqlwork` | `8007` |
| `audit` | `dbc-audit` | `8008`（mTLS `8048`） |
| `askdata` | `dbc-askdata` | `8009`（debugpy `5678`） |
| `gateway` | `dbc-gateway` | `8003` |
| `front` | `dbc-front` | `8005` |

默认启停顺序：`usercenter` → `manage` → `sqlwork` → `audit` → `gateway` → `askdata` → `front`（网关在前端之前；指定部分服务时也会自动补上 `gateway`，除非 `-Skip gateway`）。

```powershell
# 仓库根
cd e:\workspace\agent-project\database-client

# 全部：先停再启（默认前台汇总日志；Ctrl+C 停）
.\scripts\local-start.cmd

# 指定服务：空格分隔
.\scripts\local-start.cmd askdata
.\scripts\local-start.cmd askdata gateway front
.\scripts\local-start.cmd uc manage sqlwork gateway front

# 后台多窗口（脚本退出，各服务独立控制台）
.\scripts\local-start.cmd -Background
.\scripts\local-start.cmd -Background askdata gateway

# 问数关闭 debugpy；前端跳过 npm install
.\scripts\local-start.cmd -NoAskdataDebugger askdata
.\scripts\local-start.cmd -SkipFrontInstall front
.\scripts\local-start.cmd -NoAskdataDebugger -SkipFrontInstall

# 启动全部，但跳过部分（跳过的既不停也不启）
.\scripts\local-start.cmd -Skip askdata
.\scripts\local-start.cmd -Skip askdata,front

# 只启动、不先停（一般不推荐）
.\scripts\local-start.cmd -NoStop askdata

# 只打印计划（不停不启）
.\scripts\local-start.cmd -DryRun
.\scripts\local-start.cmd -DryRun gateway front

# 可选调参
.\scripts\local-start.cmd -StaggerSeconds 3
.\scripts\local-start.cmd -JwtWaitSeconds 180 askdata
.\scripts\local-start.cmd -StopWaitSeconds 30
```

等价：`.\scripts\local-start.ps1`（参数相同；`.cmd` 用于绕过 PowerShell 执行策略）。旧参数 `-Only a,b`、`-SingleConsole` 仍可用。

停止说明：

- **前台（默认）**：当前窗口 `Ctrl+C`，脚本按端口停掉本次选中模块。
- **后台 `-Background`**：关闭对应服务控制台，或在该窗口 `Ctrl+C`；再次执行本脚本会对选中模块先停再启。

问数依赖：`secrets/jwt-secret.txt`（通常由 usercenter 首次启动生成）、`secrets/mtls/clients/dbc-askdata.p12`、sqlwork `:8007`。脚本在启动 askdata 前会等待 JWT 文件出现。

### 2. 手动分服务启动（备选）

```powershell
# 2. 用户中心 :8004（schema=usercenter；Flyway 自动建 schema；会为已登记应用补客户端证书，含 dbc-audit）
cd e:\workspace\agent-project\database-client\dbc-usercenter
.\gradlew.bat bootRun

# 3. 资产管理 :8006（可与 usercenter 并行；权限注册失败只打日志，不拦启动）
cd e:\workspace\agent-project\database-client\dbc-manage
.\gradlew.bat bootRun

# 4. SQL 工作台 :8007
cd e:\workspace\agent-project\database-client\dbc-sqlwork
.\gradlew.bat bootRun

# 5. 审计 :8008（依赖 ES :9200；mTLS ingest :8048）
cd e:\workspace\agent-project\database-client\dbc-audit
.\gradlew.bat bootRun

# 6. 智能问数 :8009（依赖 sqlwork :8007、仓库根 secrets/jwt-secret.txt、审计 mTLS）
#    需 secrets/mtls/clients/dbc-askdata.p12（usercenter 登记应用后启动补发；缺则重启 usercenter 或 POST /apps/{id}/reissue-cert）
#    审计默认开启 → dbc-audit :8048；显式关闭：`$env:DBC_ASKDATA_AUDIT_ENABLED='false'`
#    **LLM 默认云端**（对齐 ai-dev-assistant `ada.llm`）：
#      base = https://dashscope.aliyuncs.com/compatible-mode ，model = qwen-max
#      密钥：`$env:DBC_ASKDATA_LLM_API_KEY` / `$env:ADA_LLM_API_KEY` 或 `secrets/askdata-llm-api-key.txt`
#    本地 Ollama：`$env:DBC_ASKDATA_LLM_RESIDENCY='local'`
cd e:\workspace\agent-project\database-client\dbc-askdata
.\scripts\run-local.cmd
# 默认以 debugpy 监听 5678，可在 Cursor「运行和调试」选「dbc-askdata: Attach」下断点
# 等待附加后再启动：.\scripts\run-local.ps1 -WaitForDebugger
# 关闭调试监听：.\scripts\run-local.ps1 -NoDebugger
# 开发热重载（与 debugpy 互斥）：.\scripts\run-local.ps1 -NoDebugger -Reload

# 7. 网关 :8003
cd e:\workspace\agent-project\database-client\dbc-gateway
.\gradlew.bat bootRun

# 8. 前端 :8005
cd e:\workspace\agent-project\database-client\dbc-front
npm.cmd install
npm.cmd run dev
```

### 3. 入口与账号

浏览器打开：`http://127.0.0.1:8005`  
账号：`admin` / `admin`  
Nacos 控制台：`http://127.0.0.1:8001`  
登录 API 示例：`POST http://127.0.0.1:8003/dbc-usercenter/auth/login`

> **前端代理**：Vite 将 `/dbc-usercenter|manage|sqlwork|audit|askdata` **一律转到网关 `:8003`**，由网关按 Nacos 做负载均衡；**禁止**前端直连业务服务端口。`dbc-askdata` 须启用 Nacos 3 客户端注册（`DBC_ASKDATA_NACOS_REGISTER=true`，OpenAPI：`/nacos/v3/client/ns/instance`）。改 `vite.config.ts` 后需重启 `npm run dev`。

### PowerShell 下 `npm` 报「禁止运行脚本」

Windows PowerShell 默认会拦截 `npm.ps1`，报错类似：`无法加载文件 …\npm.ps1，因为在此系统上禁止运行脚本`。任选其一：

1. **推荐（不改策略）**：用 `npm.cmd`，如上启动命令。
2. **当前用户放开脚本**（一次生效，之后可直接写 `npm`）：
   ```powershell
   Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
   ```
3. 终端改用 **CMD**，再执行 `npm install` / `npm run dev`。

## IDEA 运行说明

包名迁移后主类为：

- Gateway：`com.lyj.dbc.gateway.GatewayApplication`
- UserCenter：`com.lyj.dbc.usercenter.UserCenterApplication`
- Manage：`com.lyj.dbc.manage.ManageApplication`（Gradle 任务 `bootRun`，工程目录 `dbc-manage`）
- Sqlwork：`com.lyj.dbc.sqlwork.SqlworkApplication`（Gradle `bootRun`，工程目录 `dbc-sqlwork`）
- Audit：`com.lyj.dbc.audit.AuditApplication`（Gradle `bootRun`，工程目录 `dbc-audit`；需 ES）

仓库为**多独立 Gradle 工程**（非单一 root 多模块）。在 IDEA 中需把 `dbc-gateway` / `dbc-usercenter` / `dbc-manage` / `dbc-sqlwork` / `dbc-audit` 都链进 Gradle（见 `.idea/gradle.xml`）。若侧栏看不到某工程：

1. Gradle 工具窗 → 加号 / Link Gradle Project → 选对应 `build.gradle.kts`
2. 或 **Reload All Gradle Projects**
3. 再运行配置 **ManageApplication** / **SqlworkApplication**（sqlwork 为对该工程执行 `bootRun`）

工作目录须为仓库根（`bootRun` 已固定），以便读取 `secrets/`。

## 数据库重置（规范改建表后）

若本地需重建 IAM（含改用 `usercenter` schema），可：

```sql
DROP SCHEMA IF EXISTS usercenter CASCADE;
-- 若仍残留旧 public 表也可按需 DROP；开发环境不必做 public→usercenter 数据迁移
```

然后重启 `dbc-usercenter`，Flyway 会自动创建 `usercenter` schema 并执行迁移。

## 目标库联调约定（sqlwork）

对自行配置的 PostgreSQL 等目标库做写/DDL 测试时，**请只操作 `public` schema**，不要改其它业务模式中的数据。对象浏览仍可展示全部 schema；产品不按「仅 public」硬拦截（见设计 14）。
