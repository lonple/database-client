# 设计文档模板

需求文首的拍板表填完后再用本模板。默认两份文件：

- 有新服务、新 schema 或新的外部调用：`doc/设计/架构/NN-标题架构概要.md`
- 始终：`doc/设计/详细设计/NN-标题详细设计.md`

不新增边界时跳过架构概要，详细设计文首链接 `doc/设计/架构/01-架构设计.md`。章节取自 `02-智能问数架构概要.md`、`08-智能问数详细设计.md`、`09-智能问数测评详细设计.md`。

## 架构概要

```markdown

| 项 | 内容 |
|---|---|
| 版本 | v0.1 |
| 日期 | YYYY-MM-DD |
| 上游 | 需求文档 |
| 总架构 | [01-架构设计.md](./01-架构设计.md) |
| 拍板 | 从需求拍板表压缩的边界（谁可调用谁、数据落在哪） |

## 1. 设计目标

- 与需求「一句话」主路径一一对应的目标。不新增需求范围。

## 2. 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 服务 | 目录名 = Nacos 名 = URL 前缀 |  |
| 平台库 | PostgreSQL schema | 与目标库上的业务表分开写 |

## 3. 逻辑架构

用文本图画浏览器 → 网关 → 本服务 → 下游。每个框一行职责。标明模型、浏览器、manage 不能直接碰到的下游。

## 4. 边界

| 通道或调用方 | 受众 | 允许看到 / 允许调用 |
|---|---|---|
|  |  |  |

## 5. 主链路

生成（或准备）与正式执行分开写。标出用户确认点。

## 6. 小结

三五句：数据落点、调用边界、本篇不包含的邻域。
```

## 详细设计

```markdown
# ［名称］详细设计

| 项 | 内容 |
|---|---|
| 版本 | v0.1 |
| 日期 | YYYY-MM-DD |
| 服务 | `dbc-…` |
| 上游 | 需求、架构概要、对应 `doc/ui/*.html` |
| 关联 | 被调用或被改动的既有详设（含 06 前端） |

## 1. 定位与边界

**做：** 与需求 In Scope 同文。

**不做：** 与需求 Out of Scope 同文。

## 2. 工程与包

| 维度 | 约定 |
|---|---|
| 目录 / Nacos / 网关前缀 |  |
| 包名 | Java：`com.lyj.dbc.{短名}`；Python：`dbc_{短名}`，不用 `com/lyj` 目录 |

## 3. 领域模型

平台库表。每张表写用途、关键列、与工作连接上业务表的区别。不在这里发明需求未拍板的对象。

## 4. 行为设计

按需求主链路写模块职责、状态流转、失败与取消。外部调用写清：哪个组件、带什么身份、禁止谁调用。

涉及大模型或 Agent 时写明：模型可见的工具清单、人确认之后才执行的步骤、校验失败如何回到生成。

## 5. API

| 方法 | 路径 | 谁调用 | 对应原型上的操作 |
|---|---|---|---|
|  | `/dbc-…/` |  | `doc/ui/某页` 的某个按钮 |

权限码与审计事件放在同一表或紧随的表，不另开一套无权限说明的接口。

## 6. 前端

路由与页面区域对齐原型和 `06-前端与界面设计.md`。写明空态、禁用、二次确认。有增量时改 06 的路由表，并在本节链过去。
```
