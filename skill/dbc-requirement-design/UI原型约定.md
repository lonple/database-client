# UI 原型约定

原型是需求的信息架构来源，也是详细设计「前端」节的对照物。文件在 `doc/ui/`，浏览器直接打开，不单独做构建。

## 两类页面

| 类型 | 现例 | 要求 |
|---|---|---|
| 产品页 | `智能问数.html`、`智能问数-工作台.html`、`工作空间详情.html` | 真布局，主路径用链接或按钮走通 |
| 说明页 | `智能问数-架构与流程.html`、`智能问数-LLM与Agent工作流.html` | 讲组件与时序；不代替产品页 |

产品页未点击走通之前，不把该路径写成已定交互。

## 页面骨架

产品页沿用 `common.css` 与现有壳，不新做一套视觉：

- 顶栏：`.logo`、`.nav-l1-item`、当前页 `.active`、右侧用户名与退出。
- 一级顺序与 `index.html`、`doc/README.md` 一致。改顺序须先改这两处和 `06-前端与界面设计.md`。
- 内容：面包屑、`.page-title`、左栏、主区。进入门槛用空态（如「请先选择工作空间」），未选择时链接不放行。
- 新建、确认类用 `.modal-mask`。必填标签标 `*`。删除用二次确认，不在原型里一键消失后无可撤销说明。
- 列表用贴近业务的示例数据，不用 lorem。
- 页脚 `.note` 写已拍板约束，并链接到需求文档。说明数据从哪来、谁有权限、什么不做。

## 与文档的对应

每个新产品页：

1. 在 `doc/ui/index.html` 按模块加卡片（标题 + 一句能力 + 「打开」）。
2. 需求文首「UI」行链到该文件。
3. 详细设计「前端」节按该文件的区域写路由与状态，不增加原型上没有的按钮。
4. 原型新增的按钮、字段、`.note`，若需求里没有，先回到需求分析补拍板，再留在原型上。

## 从原型回写需求时要摘的内容

- 所有 `href` 目标：主路径与分叉。
- 表单字段与是否必填。
- 按钮的可用 / 禁用条件。
- `.note` 全文。
- 空态、失败、无权限时的文案。
- 弹窗关闭后用户留在哪一页。
