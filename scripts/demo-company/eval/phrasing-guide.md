# 测评问话语术标准（出题人）

目标用户：开发 / DBA / 业务运维日常查数。问题要像人口语，不要像考试卷标题。

## 1. 语气与结构

| 推荐 | 避免 |
|------|------|
| 「帮我查一下…」「看下…」「有没有…」 | 「请查询表 X 满足条件 Y 的记录」 |
| 带业务键：工号、单号、项目号、客户编码、名称 | 内部自增 id、「主键 1」、裸数字行号 |
| 时间用口语：去年、上季度、近 30 天、2025 年 3 月 | 过多 ISO 堆砌（可用一句带上即可） |
| 条件用自然话串起来 | 「年份 / 部门 / paid」式罗列；英文字段名 |
| 偶尔省略主语（「平台研发部现在多少人」） | 一次问五件无关的事 |
| 事实表（请假/拜访等无单号）从关联主数据切入 | 「请假单主键=1」这类用户看不到的口径 |

## 2. 标准扩写模板（用于生成期望 SQL）

出题时先写**口语题**，再在备注里写**规范化意图**（不给模型）：

```text
口语：帮我看下工号 E240012 现在还在不在职，哪个部门的。
意图：emp_no=E240012 → 在职口径见 answer-key；返回 emp_no,name,dept_name,employment_status
验证：key_set(emp_no) 或 scalar 单行
```

```text
口语：PRJ2025005 这个项目都有谁，角色是啥。
意图：project_code 关联 prj_project_member + hr_employee；order by emp_no
验证：order_by(emp_no)
```

## 3. 分类话术样例

### 单表条件

- 「把销售部花名册拉一下，只要还在的。」
- 「工号 E230005 入职是哪天？」
- 「客户 C0004 现在什么状态？」

### 多表直接关联

- 「报销单 RB20250100004 是谁提的，哪个部门。」
- 「订单 SO20250100004 对应哪个客户名称。」

### 单表 / 多表统计

- 「2025 年各部门入职大概多少人。」
- 「按产品线看去年签约金额排个序。」

### 治理 · 看板（口语直说 + 必写返回字段）

- 「工号 E210002 对应哪些职级？把职级编码列出来。」
- 「按客户统计加班单数量，取前 20，需要返回客户编码、条数。」
- 期望 SQL：两表直连即可，勿为治理分硬加第三表 / EXISTS / WITH。
- 禁止：「挂得上的…」「换粒度看板…」「经…关联上的…」「需要返回编码」。

### 治理 · 中断补全（题面故意含糊 + 预置补充）

- 题：「活跃客户上季度贡献多少。」
- 补充轮次：`活跃=status=active 且上季度有非 cancelled/draft 订单`（补充话术可含技术口径，题面不要）

### 治理 · 中断不补全（应拒答）

- 「把有问题的订单都查出来。」（不定义「有问题」）
- 「异常考勤名单导一下。」（不定义异常）

## 5. 打磨原则（已落地）

1. **信息顺序稀疏倒置（约 1/4）**：多数题主句直叙、语义清楚；少数才换备选语序，备选也不得把句子弄含糊。
2. **请求开场稀疏（约 1/4）**：`请帮我` / `请帮我查下` 等；多数直说事。
3. **禁止题面出现英文字段名 / 枚举字面量**：如 `status`、`paid`、`leave_date`、`emp_no`；用「已付款 / 在职 / 工号」等口语。技术口径只写在期望 SQL 与 HITL 补充里。
4. **条件用自然话连接**：如「把销售部在 2025 年已经打款的报销单号列出来」，不要「条件：2025 / 销售部 / paid」。
5. **引用业务说法**：可用空格、中文引号 `“”` 或英文引号 `""`；**禁用**直角引号 `「」`。
6. **禁止题面夹元数据**：不要写 `（用例 TPL_xxx）`、`核对用第 N 版` 等与业务无关的话术；撞车用自然改写区分。
7. **治理 HITL**：每条独立场景 + 独立 `hitl_replies`。
8. **拒答类**：保持含糊词，不给可执行定义。
9. **维度汇总金标保持单键**：期望 SQL 不要堆 id+code+name；问数键不一致时由比对器按目标库同等唯一键表补全后再比。
10. **禁止用户不可见的内部 id**：题面与过滤条件不得用「主键 / 内部 id / 裸数字行号」；无业务单号的事实表从工号、客户编码、会议室编码等关联主数据切入。JOIN ON 技术键可以，WHERE 过滤必须是业务可感知值。
11. **复杂 SQL 必写返回字段**：多表关联 / 治理类若 `compare_spec.requiredColumns` 非空，题面须用口语写明「需要返回… / 把…查出来 / 把…带出来」，与必须返回列一致（用中文业务名，不用英文字段名）。
12. **有序 TopN 必写并列次序**：若期望 SQL 为 `ORDER BY 度量 DESC, 维度键`（`compare_spec.order_columns` 含度量+维度），题面须写清「按…从高到低排序，相同则按…升序」，避免模型只写主度量排序导致并列乱序被判 PARTIAL。
